# docs/ — 文档体系规则

约束 `docs/` 下每一页。人类入口是 `README.md`；项目总约束在上级 `AGENTS.md`。
本文件不承载知识，只规定**页面放哪、长什么样、怎么保持不腐烂**。

## 1. 页面放哪

| 目录 | 放什么 | 语言 |
|---|---|---|
| `standard/` | 登记表：术语、来源口径、**裁定登记表** | 中文 |
| `architecture/` | 系统怎么组成的、依赖朝哪、为什么 | 中文 |
| `decisions/` | 本项目自己的取舍（编号 `D-nnnn`） | 中文 |
| `backlog/` | 待办票据，状态即目录 | 中文 |
| `acceptance/` | 代理运行的验收规程 | 中文 |
| `evidence/` | 交付清单与验证证据 | 中文 |
| `development/` | 代理工作细则 | 中文 |

- 人工文档**只有中文一份**（`docs/decisions/active.md` D-0016）。**不建 `docs/en/` 镜像**，
  除非将来真正国际化。
- 规则类知识**不放这里**，放 `standard/`；架构推演放 `architecture/`；一次性过程记录不进文档。

## 2. 一页长什么样

一页回答**一个问题**，标题就写明读者读完能做什么。
结构：目的（一句话）→ 正文 → 相关阅读（3–6 条链接）。

- 用表格而不是大段散文来承载枚举信息（角色、状态、流程、对比）。
- 每条规则断言必须能指到引用或裁定号（见 `standard/sources.md`）。
- 命令与输出必须是**跑出来的**，不是记忆里的。

## 3. 三类文档不许混

这是本项目最容易犯的错，单独规定：

| 类型 | 载体 | 改主意时怎么办 |
|---|---|---|
| 游戏规则 | `standard/rulings.md` + 源码注释引用 | 改裁定 + **补回归测试** |
| 项目取舍 | `decisions/active.md` | 新增决策号，旧的标 `Superseded by` |
| 待办工作 | `backlog/` | 移动票据文件 = 改状态 |

把规则争议写进决策表，会让"这是游戏的规定"和"这是我们的选择"分不清——
而这两者对使用者的含义完全不同：前者说书人必须遵守，后者说书人可以提意见改。

## 4. 真话

- 我们自己的代码：引用**路径 + 引文**，**不写行号**（行号会漂）。
- 百科：引用**页名 + 抓取日期 + 区域**（见 `standard/sources.md`）。
- 界面截图、运行日志、测试输出：来自一次真实运行。
- 不确定就写进 `rulings.md`，**不写含糊话糊过去**。

## 5. 索引纪律

- **人类读者会进入的目录**有 `README.md` 当索引，索引只列本目录的页。
- **代理专用区**（`acceptance/`）用 `AGENTS.md` 当索引，不用 `README.md`。
- `backlog/README.md` 是**指针表**不是摘要：一行 = 标题 + 链接 + 优先级 + 一句"它是什么"。
  事实（决定、日期、进度、结论）只活在票据里，不重复进索引——重复的两份必然分叉。

## 6. 防腐烂

- 结论沉淀下来后，删掉过程记录（git 里有历史）。**删，不要归档**——归档会招来陈旧阅读。
- **仓库根之下**的每份指令文件（含本文件）**不超过 5,120 字节**：它只路由与约束，不装知识。
  根的 `AGENTS.md` 不在此限——它是长文入口。超限由门禁强制（超限即红）；当前余量最紧的是 `web/AGENTS.md`。
- 术语先在 `standard/terminology.md` 登记，再在别处使用。
