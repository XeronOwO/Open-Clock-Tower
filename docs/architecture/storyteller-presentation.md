# 说书人端呈现：魔典主视图 + 数据下钻

> 本页回答一个问题：**说书人端的呈现层怎么组织，才能"以席位为中心"看局面，又不丢审计与兜底。**
> 工作项：`docs/backlog/done/grimoire-view.md`；相关决策：D-0018（单 SPA 两套视图）、
> D-0012（信息只在服务端投影）、D-0015（状态账只记事实与归因）、D-0013 §5（玩家端不泄漏进度）。

## 1. 现状（审视起点）

| 组件 | 现在做什么 | 读什么 | 审视结论 |
|---|---|---|---|
| `StorytellerPanel.vue` | 连接 / 票据 / 回执 / 两栏布局装配 | 整份 `StorytellerViewDto` | 保留：仍是容器与命令回执的唯一出口 |
| `StatusStrip.vue` | 阶段 / 控制 / 槽位 / 卡点摘要 | `view` | 保留：顶部状态条 |
| `StepDigest.vue` | 当前步骤摘要、归因、选项行为 | `view` | 降为**数据下钻** |
| `SeatLedgerPanel.vue` | 状态账逐维度 | `view.seats` | 降为**数据下钻** |
| `SeatChangeTimeline` / `EffectChainPanel` / `LedgerPanel` | 最近变化 / 效果链 / 两本账 | `view` | 降为**数据下钻** |
| `AssignmentControl` / `OperationsControl` | 开局分配 / 兜底与推进 | `view` + `sender` | 保留为**局务**，不随席位走 |
| `DecisionPanel` / `StateReportControl` | 裁定点 + 卡点（代填 / 作废）/ 状态上报 | `view` + `sender` | **拆解**：按席位就近呈现（本票主改造） |

被现行结构放大的问题：席位信息散在四张表里，说书人要"逐行读"；卡点、待裁定、状态上报
分别在左栏不同的面板里，操作要来回找——这正是需求方要求"更像一款游戏"的痛点。

## 2. 目标结构

```text
StorytellerPanel                     连接 / 票据 / 命令回执 / 布局装配
├── StatusStrip                      顶部状态条（阶段 / 槽位 / 卡点）
├── 降级横幅（StorytellerPanel 内联）  恢复 / 重建失败时置顶显示（原因 + 发生时间）；只说书人可见
├── GrimoireView                     主视图：席位圆环（窄屏退化为纵向列表）
│   ├── GrimoireSeatCard × N         席位牌：角色 / 阵营 / 生死 / 维度标记 / 提示标记
│   │                                 当前槽位 / 卡点 / 待裁定 的归属席位带高亮
│   └── GrimoireSeatConsole          席位操作台（贴着圆环）
│       ├── 当前待办：卡点（代填 / 强制作废）与待裁定——带归属席位标签、始终可见，
│       │             不因选中席位不同而被藏起来（兜底入口永远开着）；可一键"定位到该席"
│       ├── 归因明细：选中席位的全部已观测事实 + 挂在它身上的效果
│       └── 状态上报（目标 = 选中席位；一旦开始填写就锁定该席）
├── GrimoireDataDrawer               数据与审计（可展开）：StepDigest + 四张表
└── 局务区（右列）                   兜底与推进 / 开局分配
```

**职责单一**：`GrimoireView` 只做布局与选中态；`GrimoireSeatCard` 只渲染一个席位牌；
`GrimoireSeatConsole` 只做该席操作台；派生计算全部在 `web/src/display/grimoire.ts`（纯函数）。
组件之间不互相发命令，命令仍只有两条路径：`storytellerCommands` 的 `sender`。

## 3. 数据与来源（单一来源）

- 主视图与下钻面板使用**同一份** `StorytellerViewDto`（同一次推送）——矩阵行 6 的"同源"由此保证。
- 席位牌模型由 `display/grimoire.ts` 从 `view.seats` / `view.effects` / `view.annotations`（说书人注记，D-0019）/ 当前槽位字段派生；
  "未观测 ≠ 默认值"：没有事实的维度显示"未观测"，**绝不**画成"存活 / 健康"。
- 裁定归属与整局标记直接读服务端字段：`awaitingDecisionSeat`（谁在等，触发格 / 触发型裁定也可归属）、
  `fangGuInfection`（魔典中心「限一次」）、`barberNight`（「今晚理发」）；前端不解析裁定 id、不做规则推断。
- 槽位读数是**显示层口径**：`planCompleted` 显示「已完成」、否则封顶在 1..slotCount
  （`slotIndex == slotCount` 是内核"已走完"的正常表示，直接 `+1` 会读出「2 / 1」）。
- 服务端数据按不可信输入处理：`normalizeStorytellerView` 之后再做有界化，坏字段只降级该格。

## 4. 审视结论（每一条都有理由）

| 问题 | 结论 | 理由 |
|---|---|---|
| 主视图容器 | 席位圆环；席位顺序 = 服务端席位号 1..N | 席位号是服务端事实，顺序不是呈现层可以重排的 |
| 拖拽交互 | **不做**自由拖拽重排 | 顺序一旦可变，就出现"本地顺序"这个第二事实来源；本票没有任何规则需要重排 |
| 选中态 | 本地呈现态 `selectedSeat`，默认跟随当前槽位行动者 | 呈现态允许本地（`web/AGENTS.md` §4）；不写任何游戏状态 |
| 提示标记 | **事实派生**：中毒 / 醉酒 / 疯狂要求（R-0003）+ 该席全部效果链接（含已终止，终止态另标）；阵营用牌圈颜色 + 文案。**说书人注记**（D-0019）：席位锚定自由文本 token，牌面截断显示、全文进 `title` 与操作台 | 2026-10-02 自由文本另立票据；2026-10-03 定为"本局级 · 进事件流 · 只说书人可见"（D-0019）；"挂起"态当前投影不可区分（`EffectDto` 只有 `terminated`），记为边界 |
| 玩家名条 | 只显示席位号，不引入昵称 | 票据边界；昵称是另一个数据面能力 |
| 操作就近 | 席位操作台承载该席的裁定 / 卡点 / 上报；全局兜底仍独立成区 | 命令入口不复制，`sender` 仍只有一份 |
| 数据面板 | 四张表 + 当前步骤放进可展开的"数据与审计"，默认收拢 | 票据第 6 条：审计不能被游戏化挤掉，也不该继续抢占主视图 |
| 小屏 | 圆环退化为纵向席位列表，同一 `GrimoireSeatCard` | 票据第 8 条；CSS 断点切换，不改数据与组件契约 |
| 降级位 | 只在说书人视图置顶显示（`health`：degraded / reason / since）；玩家投影不下发，降级房间玩家加入显式失败但文案中性 | 票据 `room-health-degradation-flag` 第 3 条（玩家侧单独决策）；D-0012 §4.3 |
| D-0018 呈现边界 | **不修订** | 仍是单 SPA 两套视图；玩家侧"不出现说书人字段"的门禁不变 |
| 素材 | 全部 CSS 自绘几何 + 文字（类型色环、帷幕、标记圆点） | 不引入官方美术；无第三方位图素材，无需来源登记 |

## 5. 依赖方向

新增组件全部位于 `web/src/features/storyteller/`，只依赖 `web/src/contracts`、`web/src/display`、
`web/src/services`；**不新增服务端契约**（本票是纯呈现改造），玩家端代码路径不动。

## 6. 验收对应

| 矩阵行 | 运行时怎么证明 |
|---|---|
| 1 打开看板 | 真机截图：圆环 + 每席角色牌可见 |
| 2 中毒 / 醉酒 | 席位牌标记出现；操作台能追到归因（原因 / 归因方 / 效果 id） |
| 3 死亡 / 复活 | 帷幕标记出现 / 解除（截图对比） |
| 4 当前槽位 | 该牌高亮；在操作台完成一次真实裁定 / 代填（断言命令回执） |
| 5 视角隔离 | 沿用主批次的反方向断言：无关玩家零活动、玩家端无他人字段 |
| 6 数据一致性 | 主视图与展开后的表格来自同一 `view`（同一次推送），同时截图 |
| 7 素材合规 | 仓库扫描：无新增位图 / 官方美术；本页第 4 节记录来源 |
| 8 小屏 | 窄视口截图：圆环变纵向列表，角色 / 生死 / 状态信息不丢 |
