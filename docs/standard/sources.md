# 来源与引用口径

> 本项目的领域知识来自**钟楼百科**。此文件规定"什么算证据、怎么引用、抓什么、不提交什么"。
> 违反本文件的第一条后果是：代码里的规则看起来对，实际是凭记忆编的。

## 1. 权威来源

| 来源 | 定位 | 说明 |
|---|---|---|
| 钟楼百科 <https://clocktower-wiki.gstonegames.com> | **唯一权威公开来源** | MediaWiki，中文。角色页、规则页、相克规则页 |
| 印刷规则书正文（第三方逐字提取文本） | 权威补充；**不要求实物原件** | 若与百科冲突，记入 `rulings.md`，不擅自取舍。本地留档：`references/rulebook/`（正文 gitignored）+ `references/rulebook-index.json`（来源 URL / 抓取日期 / 字节数 / SHA256），由 `tools/fetch-rulebook.ps1` 生成。引用写法：「印刷规则书提取文本 · 2026-10-04 抓取 · &lt;区域&gt;」（规则书原文为英文，`rulings.md` 中的引文为中文译文，原句以留档文本为准）。2026-10-04 需求方定案：**不再以「拿到实物原件」为复核条件**——百科是唯一权威公开来源且持续更新；提取文本只留来源 URL + 哈希备追溯 |
| 官方设计师公开回复 | 权威补充 | 引用时必须带出处链接与日期 |
| 社区解读 / 攻略 / 视频 | **不作为规则依据** | 只能用来**发现**疑点，疑点必须回到上面三条求证 |

## 2. 百科内部的可信度层级

百科自己的《钟楼谜团隐性规则汇总》第 7 条已经声明：角色详解的"角色简介""运作方式"
**不考虑中毒醉酒及特殊互动**，跨剧本互动"请勿完全死板依照"。据此定层级：

| 层级 | 页面区域 | 用法 |
|---|---|---|
| 1（最高） | 角色页的「**规则细节**」、页《**相克规则**》 | 直接构成实现依据 |
| 2 | 规则页：《重要细节》《钟楼谜团隐性规则汇总》《规则概要》《规则解释》，以及各「能力类别」页（中毒/醉酒/疯狂/回溯型能力/互动干扰…） | 构成实现依据 |
| 3 | 角色页的「**范例**」 | 视为**回归测试用例**；与 1、2 冲突时以 1、2 为准并登记裁定 |
| 4 | 角色页的「角色简介」「运作方式」「提示标记」 | 实现参考；跨剧情互动时不可死板照搬 |
| 5 | 角色页的「提示与技巧」「伪装成 X」「背景故事」 | **不是规则**，只用于理解设计意图与做 UI 文案 |

## 3. 引用格式

代码注释、测试名、文档中引用规则时，统一写成：

```text
百科《占卜师》· 2026-10-01 抓取 · 规则细节
```

- 页名用 `《》` 包裹，必须是百科上的**真实页名**。
- 日期是**抓取日期**，不是百科的编辑日期。
- 区域名用百科上的真实小标题。
- 不允许出现"百科上说……"这类无页名的引用。

## 4. 抓取与留档

- 抓取走 MediaWiki API，不用 HTML 刮取：
  `api.php?action=query&prop=revisions&rvslots=main&rvprop=content&format=json&titles=...`
- **正文不进仓库**。原始 wikitext 落在 gitignored 的 `references/wiki/`，只供本机开发取证。
  理由：百科正文属他人作品，MIT 仓库不夹带。
- 进仓库的只有**索引**：`references/wiki-index.json`，记录每页的
  页名、抓取日期、字节数、SHA256。它让"某条引用的正文有没有被改过"可被复核。

## 5. 硬规则

- `[CRITICAL]` **禁止凭记忆写规则。** 任何规则断言都必须能指到一条引用或一条 `rulings.md` 条目。
- `[CRITICAL]` 抓不到、看不懂、百科没写的情形 → 一律登记 `rulings.md`，不许隐藏、不许猜。
- `[RULE]` 引用与实现不一致时，先改实现；确认是引用过期才更新引用，并说明抓取日期变化。
- `[RULE]` 同一规则在多页出现且说法不同 → `Contested` 条目，双方页名都记下。
