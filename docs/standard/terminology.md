# 术语表

> 一个词在录入本表之前，不得出现在代码标识符、界面文案或文档正文里。
> 本表是**正名的唯一出口**：同一事物只能有一个中文名、一个英文 slug。

## 1. 选词规则

- **中文名**以钟楼百科页名为准。需求方口语与百科不一致时，百科胜出，口语形式记为**别名**。
- **英文 slug** 用 kebab-case，取自官方英文名（如 `sects-and-violets`）；没有官方英文名时用约定译名。
- **代码标识符**一律用英文 slug 的 PascalCase / camelCase 形式，禁止拼音、禁止中文转写。
- 界面只显示中文名（首版不做多语言，见 `docs/decisions/active.md` D-0016）。
- 别名不进入标识符，只用于**搜索和纠错提示**。

## 5. 玩家状态（Player States）

**这是内核最重要的六个词。** 依据：百科《重要细节》三——"玩家的状态有：角色、阵营、生死、醉酒、中毒、疯狂"，
且"状态与玩家绑定，而不与角色绑定"。

| 中文名 | slug | 取值 | 魔典中可见 |
|---|---|---|---|
| 角色 | `character` | 具体角色 | 是 |
| 阵营 | `alignment` | 善良 / 邪恶 | 是 |
| 生死 | `life` | 存活 / 死亡 | 是 |
| 醉酒 | `drunk` | 醉酒 / 清醒 | 是 |
| 中毒 | `poisoned` | 中毒 / 健康 | 是 |
| 疯狂 | `madness` | 被要求 / 未被要求 | **否**，仅由说书人裁定。见 `rulings.md` R-0003 |

补充词：**席位** `seat`（玩家在圆桌上的一席，一局内稳定；状态属于席位）/**存活** `alive` / **死亡** `dead` / **即将被处决** `about-to-be-executed`。

## 7. 机制（Mechanics）

| 中文名 | slug | 说明 |

| 信息结果 | `information-result` | 说书人裁定的信息内容 + 「可能为假」标记；标记**只说书人可见**（三-1：不要告诉玩家他醉酒或中毒） |
| 常驻效果 | `standing-effect` | 与局面持续一致的效果（如诺-达鲺的邻近镇民中毒），由固定点对账维护 |
| 效果维度 | `effect-dimension` | 持续型效果压制哪一维玩家状态（中毒 / 醉酒），维度解除据此可算（D-0015 推论 1） |
| 固定点对账 | `settlement-reconcile` | 提交前把常驻效果与由效果压制的维度算到一致；不收敛显式失败 |
| 复盘 | `replay` | 在魔典圆盘上按事件序号逐步回放整局的**呈现投影**：不建第二账本、不写新事件；进行中对玩家零下发，`GameEndedEvent` 之后才开放（R-0043 / D-0020） |
| 复盘步骤 | `replay-step` | 复盘时间轴上的一个原子步骤：与事件流 1:1（显式排除项见 D-0020），顺序 = 事件序号，不跳步、不合并 |
| 复盘标记 | `replay-marker` | 复盘步骤在圆盘上的可视化词汇（击杀箭头 / 死亡 / 换角 / 换手 / 中毒 / 醉酒等）；与实时魔典复用同一套组件与口径 |
| 结构版本 | `schema-version` | 库文件头里的一个整数（SQLite 的 `user_version`），含义只有一条：**这个库的结构被哪些迁移改过**。它不表达"程序版本"；与程序支持到的最新版一比，只有"库旧"（自动补迁移）与"库新"（拒绝启动）两种状态（D-0035） |
| 迁移 | `schema-migration` | 一次结构演进：版本号 + 说明 + 是否**不可逆** + 守卫式动作（先看现状再动手）。清单只有一处（`SchemaMigrationCatalog`），DDL 也只许写在那里（D-0035） |
| 结构核对 | `schema-guard` | 启动时把"库里的形状"与"EF 模型的形状"逐项比一遍（表 / 列 + 类型 + NOT NULL / 主键 / 显式索引），分三档：**可自愈**（缺索引）· **致命**（缺表 / 缺列 / 形状不符，拒绝启动）· **不算错**（多出来的东西 = 回滚后的正常形态）（D-0035） |
| 单实例锁 | `instance-lock` | 库文件旁边的 `<库名>.lock`：以独占方式打开并一直握着，同一份库只允许一个服务进程；停机后文件还在是正常的，**不要删**（D-0035） |

补充词：**施加者** `applier`（产生这条效果的一方，即效果的来源席位）/**作用对象** `target`（这条效果落在谁身上）。
