# 零信任安全模型：鉴权、命令校验与信息隔离

- Status: Review
- Priority: High
- Depends on: 建解决方案、项目骨架与门禁工程

## 要解决的问题

现在没有任何鉴权与命令校验。对于《血染钟楼》这类**信息本身就是胜负**的游戏，
一个能被客户端篡改的服务等于没做：

- 玩家可以伪造"我是 N 号"直接读别人的牌；
- 玩家可以在不该行动的阶段提交行动；
- 玩家可以提交一个根本不合法的选项（比如让僧侣保护自己）；
- 玩家可以把自己的视角"升级"成说书人视角，一眼看穿全场。

需求方明确：虽然是私下里的小服务，**也要做好鉴权、对客户端零信任**。

## 要做的事

1. **两级凭据**（`docs/architecture/current.md` §4.1）：
   `SessionTicket`（整局身份）+ `ConnectionCredential`（绑定到下发它的那条连接，重连重新出示）。
   票据只用于**定位会话**，不用于**授权**——每次请求都按当前状态重新判定权限。
2. **四道闸**中间件/管线（§4.2）：身份 → 幂等 → 阶段 → 合法性（幂等提前到阶段闸之前，理由见架构 §4.2）。
   任何一闸不过：**拒绝 + 记录 + 不改状态**；拒绝日志带上下文（谁、哪一闸、什么输入）。
3. **信息隔离在服务端投影强制**（§4.3）：一个事件流，按接收者产出说书人视图 / 各玩家视图；
   越权资料**根本不下发**。
4. **前端防御性渲染**（§4.4）：把服务端数据当不可信输入，长度/类型/范围都处理。
5. **负向测试套件**（本票据的重点，见验收矩阵）：不是测"正常能进"，而是测**"越权进不来"**。

## 实施方案（2026-10-02 架构审视）

### 1. 现状清点（已有 / 缺口）

已有：四道闸骨架 `CommandGatePipeline`（身份→幂等→阶段→合法性，拒绝带 gate/code/actor/seat/command
审计日志，`GameSession.Reject`）；身份由服务端推导（`GameHub` 经 `ConnectionRegistry` 连接→席位/说书人，
命令不带身份声明）；玩家投影白名单（`PlayerEventProjection` / `PlayerView`）与玩家端字段门禁；
幂等回执、阶段与选项合法性校验若干分支；前端无裸 HTML、`display/format.ts` 已有部分防御。

缺口（本票要补）：

1. `ConnectionCredential` 完全缺失——`SeatTicket` 仅"定位会话"（占位），命令不携带连接级凭据，
   矩阵行 2 / 3 / 10 没有防线可测；
2. 身份闸只依赖 Server 内存绑定，没有「凭据 ↔ 下发它的连接」的显式校验与旧连接作废；
3. 负向用例不成体系（行 1–7、9、11 没有逐行的真宿主证据）；
4. 行 8 / 10 的**真实运行**取证装置不存在（抓帧 / 篡改客户端直调 Hub）；
5. 前端防御性渲染未逐字段审计；`PlayerProjectionLeakGateTests` 未扫 `contracts/game.ts` 与 `display/**`。

### 2. 目标域模型

- `SessionTicket`（已有）：整局有效，只用于**定位会话**，不授权；继续持久化在 `Games` 表
  （明文，本机自用；at-rest 加密不在本票）。
- `ConnectionCredential`（新增，连接级）：服务端随机生成（`RandomNumberGenerator`，≥256 bit），
  **只在下发它的那条连接上有效**；Join 成功时签发并随结果下发；此后每条命令必须携带；
  连接断开、被同角色新连接替换即失效。服务端只存 **SHA-256 哈希**，固定时间比较；
  日志只写连接 id 与短指纹，绝不写明文。

生命周期：

1. `JoinSeat(ticket, lastSequence)`：校验票据 → 作废该席位旧连接凭据 → 签发新凭据 → 返回 `{ credential, bundle }`；
2. `JoinStoryteller(ticket)`：同上，返回 `{ credential, view }`；
3. 每条命令第一个参数是 `credential`：Server 校验「哈希存在 + 属于当前 `Context.ConnectionId` +
   身份与当前席位路由一致」→ 解析 `Actor`；不过则拒绝 + 审计，且**不触达 Application**；
4. 旧连接凭据在新连接上使用 → 连接 id 不匹配 → 拒绝，要求重新出示票据加入（矩阵行 3）；
5. 断开清理只按连接 id（沿用 `ConnectionRegistry.Remove` 中"不误伤新连接"的既有保护）。

### 3. 边界与依赖方向

- **Server（连接域）**：凭据签发 / 校验 / 销毁，连接 → 身份解析（唯一身份来源）；
- **Application（命令域）**：四道闸（身份闸判"这个身份能不能发这条命令"、幂等、阶段、合法性），
  统一拒绝审计；
- **Kernel**：不认识凭据与身份。

即：凭据是传输层身份提供者，四道闸是命令授权；两者不混层。

### 4. 契约（wire）

- Join 结果包装：`SeatJoinDto { credential, bundle }`、`StorytellerJoinDto { credential, view }`；
- 所有 Hub 命令增加首参 `credential`（`SubmitResponse` / `VoidRequest` / `ProxyFill` /
  `ForceAdvance` / `TakeOver` / `ReleaseControl` / `ResolveDecisionPoint` / `ReportSeatState` /
  `AssignCharacters` / `StartNight` / `RebuildRoom` / `GetStorytellerView`）；
- 先改 TS 镜像 `web/src/contracts/game.ts`（门禁方向 TS→C# 才会见红），再补 `src/OpenClockTower.Contracts/*.cs`；
- 无灰度期：直接切换，不留新旧共存（本机自用）。

### 5. 前端

- `playerGateway` / `storytellerGateway`：Join 成功后凭据只存**内存**（票据才进 `TicketStore`）；
  每条命令携带凭据；重连（重新 Join）后替换；凭据不渲染、不进日志、不进 DOM；
- 防御性渲染：`display/format.ts`（必要时加 `display/guard.ts`）逐字段长度 / 类型 / 范围校验，
  坏数据只降级该行、不白屏；新增坏载荷单测（缺字段、错类型、超长、未知枚举）。

### 6. 审计

拒绝两类都写 Warning：Server（凭据缺失 / 不匹配 / 已被替换，带连接 id 与短指纹）
与 Application（gate/code/actor/seat/command）。行 11 的证据 = 集成测试断言拒绝码 + 真机日志扫描。

### 7. 验收矩阵的载体（行 → 怎么验）

| 行 | 载体 |
|---|---|
| 1 | 集成：2 号凭据不能取他人数据（无按席位取视图的 API；改用他人请求归属 + 说书人接口反例证明） |
| 2 | 集成：未 Join 的连接发命令 → 拒绝（无凭据） |
| 3 | 集成 + 真机：新连接持旧凭据 → 拒绝，须重新出示票据；同席并发抢占只留一条有效凭据 |
| 4 | 集成：命令面无身份参数；玩家调说书人命令 → 身份闸拒绝 |
| 5 | 集成：无挂起请求 / 阶段不符时提交 → 阶段闸拒绝（平台尚无白天阶段，记录边界） |
| 6 | 集成：选项不在服务端合法集合 → 合法性闸拒绝（僧侣未实现，用等价非法选项） |
| 7 | 集成：同幂等键重复投递 → 同一回执、事件只增一次 |
| 8 | 真机：篡改客户端记录玩家收到的全部载荷 → 越权字段名与其他席位角色 0 命中（浏览器原始帧抓包未做，见验收证据的边界） |
| 9 | 真机：无关玩家窗口零活动采样（沿用 E4 并加严） |
| 10 | 真机：Node SignalR 客户端用伪造 / 冒用 / 旧连接凭据直调 Hub，并尝试越权改他人状态 → 全部被拒（命令面无自称身份的参数） |
| 11 | 集成断言 + 真机 `batch-run.log` 扫描 gate/code 上下文 |

### 8. 门禁补充（实际落地）

- 新增 `CredentialSecurityGateTests`（4 条）：凭据必须是密码学随机（非 Guid / 时间）、存储只有哈希且
  固定时间比较、服务端日志模板不得出现 `{Credential}`、前端网关不得碰 `localStorage` / `innerHTML`；
- 玩家侧泄漏门禁：可扫文件加 `SeatJoinDto.cs`，说书人专属类型名单加 `normalizeStorytellerView`；
- 既有门禁保持，先红后绿验证（四条新门禁在本轮门禁运行中同样参与）。

### 9. 不做（本票边界）

- 全局票据轮换 / 撤销管理界面：本票的"撤销"= 连接级凭据随连接失效与重绑作废；
- TLS / 反向代理 / 限流（部署范畴，票据备注已排除）；票据 at-rest 加密（如需另立票）。

### 10. 自检（开工后逐条执行）

1. 每行验收都有"这一次运行"的证据，行 8 / 10 必须真机；
2. 新门禁逐条先红后绿；
3. 独立对抗性自检（只读子代理或等价）复核实现与证据；
4. 结构三问（域 / 状态属于谁 / 会不会超 600 行）+ 依赖方向无环；
5. 四条门禁全绿：`dotnet build/test/format OpenClockTower.slnx` + `cd web; npm run gate`。

## 验收证据与残余（2026-10-02）

**门禁**（全部真跑）：

| 门禁 | 结果 |
|---|---|
| `dotnet build OpenClockTower.slnx` | 0 警告 0 错误 |
| `dotnet test OpenClockTower.slnx` | 252 通过 / 0 失败（Gates 21 + Kernel 123 + Rules 57 + Integration 51） |
| `dotnet format OpenClockTower.slnx` | 通过（无改动） |
| `cd web; npm run gate` | 通过（typecheck + lint + 39 前端单测 + build） |

**真机取证**：

- 负向装置 `tools/verify-zero-trust.mjs`：**32/32 通过**（行 2 / 3 / 8 / 10 / 11 真机，
  含"他人角色值 0 命中"与"拒绝回执不含他人座位号 / 不带全局序号"；
  日志 `artifacts/web/zero-trust-run.log`，gitignored、一条命令可重生成）；
- 主装置 `tools/verify-storyteller-panel.mjs`：**91/91 通过 + 16 张截图**
  （凭据契约切换后无回归；日志 `artifacts/web/batch-run.log`）。

**独立对抗性复核（只读子代理，2026-10-02）**：发现 3 处 Medium 真实缺陷，已在本轮修复并复验——

1. **注册表并发非原子**：`IssueForSeat` 的"读旧绑定 → 作废 → 写新绑定"可被并发 join 交错，
   留下两条都有效的凭据 → 改为同一临界区完成；`Validate` 追加"凭据身份与当前席位路由一致"核对；
   新增并发用例 `Row3_ConcurrentJoins_LeaveExactlyOneValidCredential`；
2. **同连接换席位的路由分叉**：`Revoke` 不清"指向该连接"的前向席位映射，席位 A 的私有推送会投给
   持 B 凭据（甚至已撤权）的连接 → `Revoke` 清理全部指向该连接的映射，`Validate` 做一致性核对；
3. **拒绝回执是他人活动预言机**：跨席提交的拒绝消息带目标座位号、所有拒绝带全局事件序号 →
   阶段闸三种情形统一成 `phase.no_request_for_you`（取代旧票的拆分口径），拒绝回执 `Sequence = 0`。

同轮修复（Low）：Hub 参数层拒绝补审计、参数解析挪到凭据闸之后、`LoadSetupState`（会话缺失）写审计。
证据面同轮加固：收包扫描改用**真实键名**（旧词表含 `madness` / `awaitingDecision` 等永不命中的死条目），
增加"其他席位角色值 0 命中"、拒绝回执脱敏断言、行 10 增加"玩家越权改他人状态"反例。

**边界（如实记录）**：

- 行 5 的"白天阶段"与行 6 的"僧侣保护自己"依赖未落地能力：分别用"阶段未开始"与
  "选项不在服务端合法集合"作等价反例（集成套件 `ZeroTrustHostTests`）；
- 行 8 的取证是**消息级收包扫描**（篡改客户端收到的全部载荷 + 越权字段扫描）＋
  主装置的"无关玩家零活动"断言；浏览器 WebSocket 原始帧级抓包未做；
- 行 3 证明到"新连接持旧凭据被拒 ＋ 被顶替的旧连接立即失效"，并有**并发抢占**用例
  （同席 4 条连接并发加入 → 恰好 1 条凭据有效）；
- 拒绝回执现在不含他人座位号、不带全局事件序号（阶段闸三种情形统一码；
  "行 5 的白天"仍以等价反例覆盖）。

**残余（留给后续）**：

- 票据仍是明文持久化（`Games` 表）；at-rest 加密需另立票；
- Join 失败的暴力尝试只有日志、没有限流（限流属部署范畴，本票备注已排除）；
- 幂等回执只按幂等键索引、未绑定 actor（回执表没有身份列）；键是客户端随机 UUID、
  被拒命令不落回执，当前不可利用，属防御性加固项。

## 备注

本票据**不包含**传输层加固（TLS、反向代理、限流）之外的东西；那些属于部署范畴，
在第一个可运行会话出现时一并处理并记录。
