# 初始身份随机器：按官方阵营分布自动配板

- Status: In progress
- Priority: High
- 来源：用户会话提出（本票无实现；R-0035 已把它登记为"独立能力，要做须先立票据"）
- Depends on: R-0035（阵型修正的现有承载口径）；R-0041（分布表来源与口径）；R-0042（净分布合成口径）；
  D-0017（分配即事件）；D-0008 / D-0011（随机只作显式输入）

## 要解决的问题

开局分配现在完全手工：宿主 / 说书人把角色逐个分给席位（D-0017），平台既不知道
「多少人该有几个镇民 / 外来者 / 爪牙 / 恶魔」，也没有一键配板——线下要自己建盲抽袋、
自己数分布、自己处理阵型修正，线上只承担"记下来"。本票把它做成平台能力：

1. **按官方阵营分布配板**：给定人数 N，按官方「人数 → 镇民 / 外来者 / 爪牙 / 恶魔」分布表
   生成合法配板；
2. **阵型修正参与配板**：角色标记上的 `[...]` 设置调整（如方古 `[+1 外来者]`）
   只作用于初始设置；**修正可能来自任意类型**——《梦殒春宵》两名恶魔各带一条
   （方古 `[+1 外来者]`、亡骨魔 `[-1 外来者]`），其它剧本的男爵一类 `[+2 外来者]` 是爪牙上的同族，
   镇民 / 外来者也可能有，且方向可正可负。配板必须按**修正后的净分布**生成，
   不是先按基线配完再补一句提示；
3. **随机可重放**：随机只作为**显式输入**（种子或抽取结果）落进分配；
   内核不摇随机、重放不重摇（D-0008 / D-0011）；
4. 说书人仍然保留自由裁量：随机是**建议**，可重摇 / 手改后提交，最终以显式分配为准（D-0002）。

## 验收矩阵

| # | 场景 | 期望 | 证据 |
|---|---|---|---|
| 1 | 官方分布表 | 5–15 人逐点给出各类型数量；逐行标注取证等级（R-0041：5 行百科出处 + 6 行外推 Open） | 规则单测（逐行）+ R-0041 登记 |
| 2 | 阵型修正叠加 | 任意类型角色的 `[...]` 修正参与净分布计算；正负修正、多个修正同时在场都成立（同类先加总） | 规则单测（逐条修正 × 组合） |
| 3 | 修正超池 / 冲突 | 按官方口径**钳制并显式披露**（R-0042：12 人例 → 外来者封顶剧本池）；**结构性不可能**才显式失败（人数不在表内 / 基础分布超池 / 最终数量为负），不静默、不悄悄降级 | 钳制披露单测 + 失败路径单测 + 文案 |
| 4 | 随机可重放 | 随机结果作为显式输入进分配事件；同一事件流重放产出同一配板，重放不重摇 | 内核 / 集成用例（重建对比） |
| 5 | 角色唯一与席位 | 同一角色最多一个、总席位 = 人数、逐席分配；重复抽取不产生重复角色 | 规则单测 + 真机装置 |
| 6 | 说书人裁量 | 一键随机后可重摇 / 手改；提交仍走既有分配命令面（D-0017），不新增第二套分配路径 | 真机装置截图 + 命令面结构审查 |
| 7 | 信息隔离 | 配板结果只说书人可见；玩家只知道自己那一席（D-0012） | 零信任装置 + 投影用例 |
| 8 | 端到端 | 真机：一键配板 → 开夜 → 首夜角色按配板被唤醒 / 信息只到本人 | 装置截图逐张复核 |

## 决定与依据（开工前必须定稿的三件事 —— 2026-10-04 已定稿）

- **分布表来源**：百科**没有**承载这张表的页面——它印在实物《旅行者列表 / 初始设置表》上
  （《规则概要》6. 只引用、《术语汇总》只描述）。已穷举核对：431 个全站页名、命名空间 4 / 10 / 12 / 828、
  281 张图片名，以及**全站 431 页正文扫描**（`a/b/c/d` 记法只出现在《设置调整》）。
  表格口径登记为 **R-0041**，逐行标注取证等级与出处（页名 + 抓取日期）：
  **Attested** 7 / 8 / 11 / 12 / 14 / 15 人；**Derived**（百科例证 + 一步推算）5 / 9 / 10 / 13 人；
  **Extrapolated**（仅同带结构外推，状态 Open）只有 6 人这一行。表落服务端**单一数据源**，
  拿到实物来源后逐行改判。引用页已扩进 `tools/fetch-wiki.ps1` 显式页表并重抓（**87 页**，
  同一天重跑，旧页哈希与日期均不变）。
- **修正口径**：登记 **R-0042**——同类修正**先加总**、再按「剧本池 ∩ 人数约束」**钳制**、**镇民补偿**
  （默认补偿对象是镇民）；「修正超池」按官方口径钳制并**显式披露**（不判失败，依据《设置调整》12 人例）；
  显式失败面收敛为结构性不可能（人数不在表内 / 基础分布超池 / 最终数量为负）。修正只影响初始设置、不进引擎。
- **花名册权威数据**：服务端 `SectsAndVioletsRoster` 为**权威**（slug / 类型 / 中文名 / **结构化设置修正**），
  前端 `labels.ts` 只做**呈现副本**；新增 NormativeGates 跨栈镜像门禁（仿 `ContractMirrorGateTests`）
  逐项对账 slug / 类型 / 修正文本，漂移直接失败。整族核对发现：**亡骨魔也带 `[-1 外来者]`**
  （原票「只有方古」的表述过时），前后端数据本轮一并修正。

## 非目标

- 不做"配板后自动开局"；不替说书人决定要不要用随机结果（D-0002）。
- 不做跨剧本混搭配板（另见 `future/cross-script-extension.md`）。
- 不改规则引擎的结算路径；不新增"随机"这一内核输入类型——随机仍只以显式分配结果进事件流。
- 不做范围型修正（「+0~1 外来者」一类）与增减恶魔 / 特殊设置方式 / 认知覆盖 / 增加特定角色
  （《设置调整》优先级 1–3、5 的口径）；数据模型按「目标类型 + 整数增量」建，将来可扩展。
