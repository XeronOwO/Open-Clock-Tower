# 排版与上手引导优化：让版块自解释、信息降密度

- Status: Todo
- Priority: Medium
- Depends on: 无（纯前端呈现层；不涉及规则与投影面）

## 要解决的问题

当前界面的排版把大量信息平铺在一起，新玩家（包括说书人）**看不出每个版块是干什么的**、
也不知道某个数字 / 标记意味着什么：

1. **缺引导**：版块标题只说了"有什么"，没有一句能让人一眼看懂"这一块是回答什么问题的"
   （要的是标题级的自解释，不是一步步指路的新手教程）；
2. **缺解释**：术语、标记、计数没有就近的说明入口——需要「问号圆圈 + 悬停说明」这类低成本解释；
3. **语言偏硬**：面向玩家 / 说书人的文案可以直接用规则原文的口径，读起来拗口，
   需要更通俗的说法（术语仍以 `docs/standard/terminology.md` 的标识为准）；
4. **数据拼接生硬**：多个字段串在一起时（如席位 + 角色 + 状态 + 原因）像字段堆叠，
   需要连成一句人话；
5. 结果是信息量看起来很大，**上手成本高**——目标状态是「界面整洁」且「不看说明书能上手」。

本票是**呈现层工作**：不改规则、不改投影白名单、不新增事实；玩家端与说书人端的**信息隔离红线
（D-0012）不变**。

## 落地设计（开工前定稿，2026-10-05）

**两端共用（矩阵行 2 / 7 的载体）**

1. `web/src/display/help.ts`：说明文案登记表（`HelpTopicId → { title, text }`）。只解释既有术语 /
   标记 / 计数，**不新增规则知识**；涉及规则的条目直接引用 `docs/standard/terminology.md` 或裁定号
   （如疯狂 → R-0003、阻塞 → R-0009、信息裁量 → D-0002）。
2. `web/src/features/common/HelpTip.vue`：`?` 圆圈。悬停（鼠标）与点按（触屏）都能打开，
   键盘可聚焦、`Esc` 关闭；`aria-expanded` + `role="tooltip"`；文案一律取自登记表。
3. 版块副标题：每个主要版块 `h2` 下一行 `.block-question`，一句话回答"这块是干什么的"。
4. 数据拼接：状态账 / 效果链 / 操作台里"席位 + 角色 + 状态 + 归因"不再逐字段罗列，
   补一句由 `display/` 纯函数生成的连贯句子（矩阵行 5）。
5. 密度：
   - 说书人端：低频的「兜底与推进 / 开局分配」合并为可折叠的**局务**分组（默认收起；
     开夜等高频入口留在折叠之外）；数据抽屉保持默认折叠。
   - 玩家端：**当前请求提到首位**；「账号」登录后收成一行摘要（展开才是表单）；
     「同桌」改紧凑一行制；次要说明收紧。
   - 量度：装置在固定状态记录整页截图与 `scrollHeight`，前后对比（矩阵行 3）。

**姓名口径（E30 残余①）**：`LedgerPanel` / `SeatLedgerPanel` / `EffectChainPanel` / `SeatChangeTimeline` /
`AssignmentControl` / `PitHagNightPanel` / `StepDigest` / `GrimoireAnnotationControl` 八个组件
一律改走 `seatDisplayOf`（缺值走 `seatTextOf` 退「—」；无玩家名回退「N 号」），`seatLabelOf` 退场。

**明确不改**：服务端契约与投影白名单、四道闸、规则语义、命令入口数量；不引入官方美术；不新增术语
（新词先进 `terminology.md`）。

## 验收矩阵

| # | 场景 | 期望 | 证据 |
|---|---|---|---|
| 1 | 版块标题 | 每个主要版块的标题 + 一句副标题能独立回答"这块是什么 / 回答什么问题" | 截图逐块复核 |
| 2 | 解释入口 | 术语 / 标记 / 计数旁有「?」圆圈，悬停（键鼠）与点按（触屏）都能看到说明；说明文字与术语表口径一致 | 截图 + 前端单测（说明文案映射） |
| 3 | 信息密度 | 同一屏不再堆叠次要字段；主次层级（标题 / 正文 / 辅助）可辨；滚动长度较现状明显下降 | 前后截图对比 |
| 4 | 文案通俗度 | 面向玩家的关键文案改写为通俗说法，且不引入新术语（新词先进术语表） | 文案 diff 审查 |
| 5 | 数据拼接 | 席位 / 角色 / 状态 / 归因拼成连贯句子，不再出现连续字段罗列 | 截图 + 前端单测 |
| 6 | 信息隔离回归 | 玩家端仍看不到说书人专属字段（归因 / 效果 / 失效账本等），零信任装置全过 | `tools/verify-zero-trust.mjs` + 投影用例 |
| 7 | 相关族一致 | 说书人端 / 玩家端 / 复盘面板（若已有）用同一套文案与说明组件，不出现两套口径 | 结构审查 + 单测 |

## 决定与依据

- 纯呈现层：无规则依据需求；文案口径以 `docs/standard/terminology.md` 为准，
  术语变更遵循该页的唯一性要求。
- 说明文字（问号圆圈）**不承载新知识**：只解释既有术语与字段，规则断言一律指回来源或裁定号。
- 本票开工前先做一次界面信息架构梳理（现状：每屏有什么、主次与来源），再动版式——避免只是换皮。
