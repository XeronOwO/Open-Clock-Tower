# 上线就绪两步走：先审计差距，再按里程碑把安全底座补齐

- Status: In progress（M1 会话与登录态，2026-10-06 开工；M1 完成后再回第 1 步审计）
- Priority: **High**
- Depends on: 无（**第 1 步审计只读**；第 2 步里 **M1 不依赖审计**，可立即开工）

## 这一票是什么

需求方 2026-10-06 定调，原文照录：

> 「像登录功能、状态保持、jwt 认证鉴权、加盐哈希这种都是最最基础的网站功能啊……
> 这部分不好好做，那你网站的安全性怎么保证？这玩意可是放公网的，而且未来是开源社区共享使用的，
> 你这么做怎么可能让人放心使用？我们最初快速做核心功能，把这一整块框架都丢下了，
> 甚至还宣称"基本完成"，这是极其不负责任的表现。」
> 「分两步走，第一步探查整个项目，看看有哪些地方做的不合理，不符合成熟网站应有的功能，
> 第二步为正式开发，如果上下文较长，不必连着做，可以写回票证交接再做。」

这个判断成立。此前所有工作都围绕**规则内核 + 两端交互**，账号与安全只做到"能登录、能认人、够小圈子自用"，
从未按"公网 + 开源给陌生人用"的标准过一遍。已暴露的症状只是冰山一角：
刷新掉登录（说书人与玩家**都掉**，真机实测）、首页不显示"我是谁"、换面回到错误的落点——
**这些都是审计该一次性查出来的东西**，不该由需求方一个个撞见。

**第 1 步**：只读审计，把"能跑"和"敢放公网"之间的差距逐条查出来（§1）。
**第 2 步**：按里程碑把差距补成正经工程，每步有验收判据、每步真机验过再算完成（§2）。

同时立一条纪律（本票的一部分）：

- `[CRITICAL]` **不许再用"基本完成"这类说法掩盖整块缺失**。完成 = 该能力的验收判据（代码 + 测试 + 真机读数）
  逐条拿得出来；拿不出来就写"还差哪些"，不许概括成"差不多"。

# 第 1 步 · 只读审计（先查清，再动手）

**交付什么**：一份**可执行的差距清单**——每条 = 现状（代码/配置/运行读数证据）+ 差距 + 影响面 +
严重度 + 修法建议 + 怎么验证修好了。没有证据的条目不许进清单（不许写"可能不安全"这种）；
**查不出问题的维度也要写"已核对、无差距（核对方式见 X）"**，否则读者分不清"没问题"和"没查"。

## 1.1 审计维度（一个维度 = 一节，缺一节算没做完）

| # | 维度 | 要回答的问题 |
|---|---|---|
| A1 | 账号与口令 | 哈希算法/参数/盐/升级路径是否达标？口令与登录名策略是否合理？恢复码机制是否安全（熵、一次性、轮换、时序）？账号能否注销、改名、多设备并存？ |
| A2 | 会话与状态保持 | 会话在哪、活多久、怎么撤销、进程重启怎么办、刷新/换标签页/换设备各自什么行为？要不要"记住我"？极限情况（并发登录、会话表膨胀、时钟回拨）如何？ |
| A3 | 传输与部署 | 是否强制 HTTPS？安全响应头（HSTS / CSP / `X-Content-Type-Options` / `Referrer-Policy` / 权限策略）有没有？反代是否传真实 IP？限流、超时、请求体上限？明文链路上传了什么？ |
| A4 | 授权与越权 | 每个 Hub 方法**逐个**列出"谁能调"，核对服务端是否真的拦（不能只看前端不显示按钮）。重点：桌主身份、席位归属、说书人权限、跨桌越权、凭据重放、幂等键能否被他人占用。 |
| A5 | 滥用与风控 | 登录失败限速/锁定、注册滥用（批量注册）、开桌配额、单连接资源上限、超大载荷、自由文本（注记 / 公告 / 玩家名）的长度与**频率**上限。有没有账号审计日志，日志里会不会混进秘密？ |
| A6 | 数据层 | 只用 `EnsureCreated` + 启动守卫补列能撑多久？要不要正式 migration？备份与恢复有没有脚本、**演练过没有**？数据保留与删除（账号注销、桌回收、事件流体积增长）？ |
| A7 | 运维与可观测 | CI（三条门禁 + 前端 gate 目前只在本机跑）、健康检查语义、日志分级与轮转、崩溃自动重启、部署回滚、磁盘水位告警、单进程重启对正在进行的对局意味着什么？ |
| A8 | 开源与合规就绪 | LICENSE 之外还差什么：README 上手路径、配置样例与秘密管理、贡献指南、行为准则、**安全策略（漏洞怎么报）**、隐私说明（收集什么、留多久）、版本与发布流程、第三方素材许可（百科图热链口径）。 |
| A9 | 前端体验一致性 | 登录态在四个面之间的呈现是否一致（首页谁都不认识我）、刷新/返回/直接粘地址的行为是否可预期、错误提示是否说人话、手机端可用性、无障碍（键盘可达、标签语义、对比度）。 |
| A10 | 代码与架构 | 按项目自己的硬约束复查：文件行数门禁、职责单一、控制面/数据面分离、**为赶功能留下的"临时直路"**（直读库的装置、硬编码、TODO/FIXME 清点）、依赖版本与已知漏洞（NuGet / npm 审计）。 |

## 1.2 怎么做（方法，不是口号）

1. **只读**：不改产品代码；要动手验证的（如"未登录能不能调某个 Hub 方法"）写一次性探针放在 `tools/` 之外，
   探针用完删掉，读数写进清单。
2. **以运行证据为准**：涉及行为的结论必须来自**真跑一次**（真宿主 / 真浏览器 / 真部署），不能只看代码推断。
3. **覆盖反方向**：每个"允许"都要配一条"不允许"的核对（"桌主能开夜"要配"非桌主不能开夜"）。
4. **严重度分级**：`Critical`（放公网即出事：越权、明文口令、无鉴权入口）/ `High`（会被刷、会丢数据、
   体验致命）/ `Medium`（该有但可排队）/ `Low`（打磨）；每条给"如果不管，最坏会怎样"的具体场景。
5. **清单进本票**：结果写在本票 §1.4（超出 64KB 再拆 `docs/security/` 一页）；
   §2 的里程碑任务从清单逐条转过来，不许有"查出来但没人管"的条目。

## 1.3 审计出报告的门槛

- 10 个维度**逐个**有结论：差距条目（带证据）或"已核对、无差距（核对方式见 X）"；
- 每条差距都有：现状证据（文件/命令/读数）· 影响 · 严重度 · 建议修法 · **怎么验证修好了**；
- 严重度汇总表（Critical / High 各几条、分别落在哪个里程碑）；
- 明确写出**本次没覆盖的部分**（例如未做渗透测试、未做并发压测），不许留下"看起来都查了"的错觉。

## 1.4 初步线索（审计时逐一证实或推翻，**不许直接当结论**）

| 线索 | 初步观察 | 待证实 |
|---|---|---|
| 口令哈希 | `Pbkdf2PasswordHasher`：PBKDF2-SHA256 / 16 字节随机盐 / 210000 次迭代 / 固定时间比较；用户名不存在时跑假哈希对齐耗时 | 参数是否仍属当前推荐区间（OWASP 口径）、升级路径是否真能滚动 |
| 会话 | `AccountSessionRegistry`：内存、8 小时绝对过期、只存 SHA-256 哈希、可撤销 | 刷新即登出（**已实测**）、进程重启即全掉、会话表有没有上界 |
| JWT | **本项目未使用**，走的是不透明随机令牌 + 服务端会话表 | 需要论证"这比 JWT 更适合本场景"并写进决策，而不是默认省略 |
| 限速 | 未见登录失败限速 / 锁定 | 实测暴力破解成本 |
| 传输 | 明文 HTTP + 明文 WebSocket（真机 `http://`） | 是否上 HTTPS、证书与自动续期方案 |
| 安全响应头 | 未见显式设置 | 实测响应头 |
| 迁移 | `EnsureCreated` + 启动守卫补列 / 删列 | 长期是否需要正式 migration |
| CI | 三条门禁 + 前端 gate 只在本机跑 | 是否需要、放哪 |

# 第 2 步 · 正式开发（按里程碑）

## 2.1 里程碑（顺序即施工顺序）

### M1 · 会话与登录态（最高优先，已在需求方那儿翻过车）

**问题**：刷新就掉登录（说书人与玩家**都掉**，真机实测）；首页不显示"我是谁"；换面回到错误落点。

| # | 任务 | 验收判据 |
|---|---|---|
| 1 | 凭据持久化到 `sessionStorage`（刷新 / 切面 / 同标签页重开都在；关标签页即清；换设备仍只凭账号） | 装置断言：刷新后仍在原席位 / 仍在主持台；**关标签页重开 = 需重新登录**也各一条 |
| 2 | 首页显示登录身份；已登录时给"回到我那一桌"的直达入口 | 装置断言：登录后首页出现身份与入口，点一下到主持台 |
| 3 | 面板记住所在位置（从主持台离开再回来仍在主持台） | 装置断言：离开 → 返回落点 = 主持台 |
| 4 | 可撤销性不退步：改口令 / 登出后旧凭据立刻失效（含 `sessionStorage` 里那份） | 装置断言 + 集成用例：旧凭据被拒 |

**M1 实施记录（2026-10-06，本地证据批次 E51；真机读数见批次记录）**：

| # | 做了什么 | 判据与证据 |
|---|---|---|
| 1 | **凭据持久化**：新 `web/src/services/browserSession.ts` 做唯一落盘出口（`sessionStorage`；存储不可用即降级为内存并如实标注 `persistent=false`）· `accountSession.restore()` 启动即向服务端确认 · 服务端新增 `AccountHub.Resume`（只读、幂等、**不重发凭据、不续期**） | 账号装置 **39 项**（含"刷新后不重新登录、不点席位即回到原席"）· 开桌装置 **21 项**（含"刷新后第一眼不是登录卡"）· 主装置 **289 项** · `browserSession.spec.ts` 12 项 + `accountGateway.spec.ts` 11 项 |
| 2 | **首页认出回来的人**：`HomePanel.vue` 身份块（`home-profile`）+ "回到我那一桌"直达卡（`home-back-to-table`，按位置记的面决定落点） | 可用性装置 **34 项**（首页未登录态仍只指方向、不做登录） |
| 3 | **面板记住位置**：`ActiveTable{surface,gameId,seat}` 与凭据同存一条；两端 `resumeSeat` / `resumeTable` 自动回原处；**回不去就清掉位置并说明原因**（不许每次刷新重演同一个失败） | 账号 / 开桌 / 主装置（刷新回席、自动接回主持台）· 胜负装置"刷新后仍在原席" · `seamstress` 装置按 `JoinTable` 帧断言"真的重新入座了" |
| 4 | **撤销性不退步**：登出 / 口令重置 → 服务端撤销 + 本地清；旧凭据即使被塞回存储也被拒 | 集成用例 `Resume_ReturnsProfileWithoutCredential_AndRejectsRevokedSessions` · `Resume_AfterPasswordReset_RejectsOldSession_AndAcceptsNewOne` |
| 反方向 | **关标签页即清**（`sessionStorage` 每标签页一份） | 账号装置与开桌装置各一条"新标签页必须重新登录"；账号装置续判"重登后仍能回到自己那一席" |

**M1 的决策与边界**：方案与取舍登记在 `docs/decisions/active.md` **D-0029**（含"为什么不是 HttpOnly Cookie"、
"为什么不落盘连接级凭据"、"存储不可用怎么办"、"XSS 欠账记进 M3"）。
会话生命周期**不变**：8 小时绝对过期、进程重启即全失效——主装置的健康票段就是这条的运行时证据
（宿主重启后刷新**必须**重新登录，装置因此覆盖"自动接回"与"重新登录接回"两条真实路径）。

**M1 的同批产出（整族对齐）**：复核装置时咬出并修掉 4 处既有夹具漂移，都不是本轮引入、但都会让装置假红/假绿：
① `seamstress` 装置还在等 `JoinSeatWithAccount`，而 D-0027 之后玩家入座走 `JoinTable`（基线直接崩在半途）；
② 三个装置的帧收集器把**账号连接与游戏连接**的 `invocationId` 混在一个序列里匹配回执，于是 `SubmitResponse`
收到了 `ListTables` 的回执（表现为"提交明明成功、装置判红"）；
③ `retro-info` 的越权扫描拿整个载荷做子串匹配，把**公开的同桌名单**（夹具玩家名里带角色 slug）判成泄露；
④ `setup-randomizer` 的首夜槽位数还停在 13（咖啡师黄昏槽之后是 14）。

### M2 · 授权与越权（公网第一风险）

逐个 Hub 方法列出"谁能调"，服务端**确实**拦（不看前端按钮）；重点补反方向断言：
非桌主能开夜吗？能踢人吗？能看别桌视图吗？凭据重放、幂等键被他人占用、跨桌 `gameId` 混淆。
**验收**：一张"方法 × 允许身份"矩阵 + 每条一条正 / 反用例（装置或集成测试）。

### M3 · 传输与部署安全

强制 HTTPS（证书 + 自动续期 + HTTP 跳转）；安全响应头（HSTS / CSP / `X-Content-Type-Options` /
`Referrer-Policy` / `Permissions-Policy`）；`Secure` / `SameSite` 属性随 M1 的持久化方案一起定；
限流与请求上限；反代真实 IP；明文链路清点归零。
**验收**：真机 `curl -I` 读数 + 一条"HTTP 会被跳到 HTTPS"的判据 + 一份"链路上还传了什么明文"的清点。

### M4 · 滥用与风控

登录失败限速 / 渐进延迟 / 锁定；注册滥用（批量注册）与开桌配额；自由文本长度与**频率**上限
（长度已有，频率待补）；**账号审计日志**（登录、失败、改口令、开桌、锁桌），日志只写短指纹、绝不写凭据。
**验收**：限速有一条会红的用例（连续失败 N 次后被拒）；审计日志有一次真机读数。

### M5 · 数据层与运维

是否需要正式 migration（`EnsureCreated` + 启动守卫的长期代价）；备份与恢复脚本 + 一次真机演练；
账号注销与数据删除；事件流体积与桌回收；CI（三条 .NET 门禁 + 前端 gate 进流水线）；
健康检查语义、日志轮转、磁盘水位告警、回滚步骤。
**验收**：备份能真恢复一次（演练读数）；CI 至少一条流水线跑通；注销路径端到端可用。

### M6 · 开源与合规就绪

README 上手路径（陌生人从零跑起来）· 配置样例与秘密管理（现在口令 / 地址放 `AGENTS.local.md`，
公开仓库需要另一套口径）· 贡献指南 · 行为准则 · **安全策略（漏洞怎么报）** · 隐私说明（收集什么、留多久）·
版本与发布流程 · 第三方素材许可（百科图热链口径）。
**验收**：一个"陌生环境从 clone 到跑起来"的清单被真跑一遍；安全策略与隐私说明在仓库里可读。

## 2.2 施工纪律

- **一步一验，不许攒批**：每个里程碑结束都要有真机读数 + 装置 / 用例证据，写进 `docs/acceptance/batches.md`。
- **不许回归已验过的行为**：M1 会碰装置里大量"刷新即登出"的现有假设（`returnToSeat` 等），
  改装置的同时必须补"关标签页才登出"的反方向断言，否则等于把一条真实约束悄悄删掉。
- **上下文不够就交接**：本票跨两个阶段、六个里程碑，一个会话做不完；每个阶段 / 里程碑收口时按项目惯例
  产出交接提示词（工作区复核 / 已落地 / 已知缺陷 / 下一步 / 门禁注意 / 清场结果），
  下一会话接着做，**不要连着硬做**。
- **决策要登记**：会话持久化方案、是否继续不用 JWT、HTTPS 与证书方案、限速口径都属项目取舍，
  进 `docs/decisions/active.md`（新编号），不许只活在代码注释里。
