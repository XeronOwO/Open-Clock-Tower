# 角色变更装置：复盘里找不到「恶魔击杀」与「换手」两步

- Status: Done
- Priority: ~~**Medium**~~ → 结案：**装置侧缺陷，不是产品回归**
- Depends on: 无

## 判定（2026-10-07）

**不是产品回归。** 那两个步骤在复盘里**一直都在**——同一次运行里，走查器自己就读到了它们：

```
[诊断] 第 41 / 52 步 · 事件序号 186 :: 死亡 · 4 号 · 夹具玩家cc-4恶魔击杀 · 5 号 · 夹具玩家cc-klutz → 4 号 · 夹具玩家cc-4
[诊断] 第 47 / 52 步 · 事件序号 205 :: 换手 · 2 号 · 夹具玩家cc-2 → 1 号 · 夹具玩家cc-philosopher · 原行动者 2 号 · …
```

错在 `tools/verify-character-change.mjs` 的**走查器**，两处独立的缺陷叠在一起：

| # | 缺陷 | 证据（同一次运行的读数） |
|---|---|---|
| 1 | 断言写的是**拼好的整句** `5 号 → 4 号`，而 D-0021 之后席位名插在数字之间（`5 号 · 夹具玩家cc-klutz → 4 号 · 夹具玩家cc-4`）⇒ 该子串永远不存在 | 走查器**走到了**第 41 步并读到了含「恶魔击杀」的标记文本，仍判未找到 ⇒ **在 E29 写成的那天起就不可能匹配**（当时名字还没进复盘文案，之后进了，断言没跟着改） |
| 2 | 走查循环每步只 `setTimeout(0)`，不等 Vue 把新步刷进 DOM；连点快过渲染时**整段跳过** | 「换手」落在第 47 步，走查器从第 28 步一路报空到第 52 步（`第 42…51 步 :: ""`） |

**为什么当初看着像产品缺陷**：两条断言都失败在"走到最后一步都没等到"，与实际"步骤存在但断言匹配不上"的表象一致。

## 修法（先红后绿）

1. 匹配基准换成**结构化席位**（`5 号` / `4 号` 两串都须出现在**本步**的标记里），席位要求**参与判定**而不是只当走查的过滤条件——
   否则"走查落到哪一步都算过"会重新造出假绿。
2. 走查每步让出**一帧**（`requestAnimationFrame`），并在「下一步」按钮 disabled（内容加载节流、进度没变）时**重试同一步**，不把这一步跳过去。
3. **整族对齐**：`tools/verify-storyteller-panel.mjs` 的同名走查器有同一个渲染节流缺陷（那里的判据只有标记名，没被席位名咬到），同批修掉；
   复跑主装置：**289 项全过（跳过 2）**，traveller 段 31 项全过。

**先红后绿两处实测**：

| # | 改坏什么 | 实测 |
|---|---|---|
| 1 | 把席位要求改成不可能命中的 `12 号` | `失败 3 / 85`：走查一路报空 + 阴性断言判红（证明席位要求真的参与判定） |
| 2 | 修好走查后 | `verify-character-change` **89 项全过**：恶魔击杀 = 第 41 / 52 步 · 序号 186，换手 = 第 47 / 52 步 · 序号 205 |

走查器另补**卡住预算**（连续 30 次没推进即收场并写明原因）：没有它时，面板不再推进会让重试分支
无限循环——本批的红检查实测挂住过一次。

## 顺带查清的一件事（记下来，避免下次重新怀疑）

手工在真宿主上复现"方古侵染 → 新方古击杀理发师 → 理发师换角 → 尚未进入的格重绑"这条链路时，
复盘里两个标记**都正常产出**（`kill-arrow:5->4`、`role-rebind:1->2`）。所以这条链路的服务端投影没有缺口，
复盘面板的「下一步」也照常推进——不需要在这条链路上做任何产品改动。
