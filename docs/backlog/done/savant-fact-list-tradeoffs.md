# 博学者候选事实清单：取舍与条数口径（已按自决口径收口）

- Status: Done
- Priority: Low
- Depends on: `done/savant-information-picker.md`（28 条候选事实已落地，R-0057-C）

## 要解决的问题

说书人给博学者挑两条信息（一真一假）时，平台摆出来的候选清单是**首版按"常用度"取的一版**——
28 条事实定义、6 席一局展开 157 条。它已经能用（批次 E40 / E41 判过），但清单本身有三类问题，
都需要需求方拍一次板：

1. **有重复**：至少一对候选在可判定的情形下真值恒等（「恶魔与最近的爪牙相邻」与「恶魔左右相邻的席位里有爪牙」——
   **2026-10-05 已按 D1 收口**：两者是同一个事实的两种说法，共用互斥组，说书人端点一条另一条当场灰掉），
   另有一对是同一段代码换了角色类型（`minion-beside-demon` / `demon-beside-outsider`）；
2. **有浪费**：`role-in-play` / `role-dead` 对**全花名册 30 个角色**出候选，其中不在场的角色恒为假，
   一屏里绝大多数是同一句假话；`alive-count-equals` / `good-lead` 的 `0` 取值在账上永远不可达；
3. **有缺口**：百科范例里出现的两类信息现在表达不出来——「只有一名外来者在场」（按类型计数）、
   「昨晚没有人的能力未正常生效」（否定式读数）。

**这不阻塞任何功能**：清单只用不选，删一条 = 删一个 `SavantFactDefinition`，不动状态机、不动投影。
但清单是玩家最终看到的信息来源，取舍该由需求方定。

对外发布的选择才交回需求方。这一条不是那类：改的是候选清单的长度，随时可逆，且**不减少任何能说的事实**

判据（都取自项目已有依据，不是偏好）：

  「点名」组三分之二是同一句恒假的噪声；而这一组本来就是**最强也最容易毁局**的一组（见本文件 §E 组备注），
  噪声直接把要看的几条埋掉；
- 官方范例里出现的是"某个在场角色"的说法（`TC-savant-02`「舞蛇人存在于游戏中」，`docs/standard/character-examples.md`），
  没有"某角色不在场"的范例；
- 收窄与同组 `seat-character` 的口径一致（它本来就只枚举在场角色），两条事实不再互相矛盾。

## 条数口径（157 → 182 → 134）

事实定义仍是 **28 条**（A 6 / B 6 / C 7 / D 4 / E 5）。两轮下来 6 席一局的候选数是
157 →（A 类合并 / 补缺）182 →（B1 收窄）**134**（各批装置取证档实测；两轮的时点不同，
逐族数字的差里既有收窄也有当天账的不同）：

| 族（分组名） | 182 版 | 134 版 | 差 |
|---|---|---|---|
| 座位关系 | 11 | 13 | +2（票据 E42 实测时点） |
| 阵营与人数 | 35 | 41 | +6（同上） |
| 昨晚与今天 | 7 | 7 | — |
| 状态读数 | 4 | 4 | — |
| 点名 | 125 | **69** | `role-in-play` / `role-dead` 各 30 → 各 6（本局在场的 6 个角色） |
| **合计** | 182 | **134** | −48 |

| 项 | 取值 | 6 席条数 |
|---|---|---|
| `demon-minion-distance` | `1 .. ⌊n/2⌋`（距离口径） | 3 |
| `demon-neighbour-type` | minion / outsider / townsfolk | 3 |
| `alive-lead` | evil / tied / good | 3 |
| `alive-count-equals` / `good-lead` | `1 .. n` / `1 .. n−1` | 6 / 5 |
| `type-count-equals` | 4 类型 × 人数（0..n） | 28 |
| `role-in-play` / `role-dead` | **本局在场的角色**（去重；未观测的角色不进） | 各 6 |
| `seat-character` | 席位 × 本局在册去重角色 | 36 |
| `two-seats-same-team` | `C(n,2)` | 15 |

⚠️ **条数只在"该判的都判得了"的账上成立**——判不了的候选根本不出现，所以换个时点跑会差几条
（上面两列就是这么来的）。装置断的是**逐族精确值 + 总条数精确值**
（`tools/verify-retention-day-info.mjs` 的两条断言），它护的是"事实库被改动"这件事。

## 决定与依据

- **依据**：百科《博学者》· 2026-10-01 抓取 · 角色能力 / 角色简介（说书人选两条、一真一假、博学者不知道
  哪条对哪条、可以选择不要）；同页 · 范例 `TC-savant-01..04`（`docs/standard/character-examples.md`）；
  百科《钟表匠》· 2026-10-01 抓取 · 规则细节 3（距离口径）；R-0057 / R-0057-B / R-0057-C。
- **自决的部分**（A 类、B1、B2、C1、D1）：纯工程取舍，按 `AGENTS.local.md`「工作项选择与实现取舍由代理决定」
  直接落地，不再逐条请需求方拍板。B1 的改口理由见上面 B 类那一节。
- **C2 的处置（不补）**：「昨晚没有人的能力未正常生效」这条否定式读数在首版**表达不出来**，
  原因是数据面而不是懒：要断"没有人"，得先有"每名玩家的能力都观测齐"这个前提，
  而首版只在**能力未正常生效**时才落失效账本——账上没有记录既可能是"都正常"也可能是"还没观测"，
  平台不许猜（D-0015）。做成三态（none / some / 判不了）也不会凭空多出数据，
  只是把"判不了"画到界面上。**首版走自由文本兜底**；要补的话先补观测面（每条能力都给正常 / 异常回执），
  那是另一张票的体量。
