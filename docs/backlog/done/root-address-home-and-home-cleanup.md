# 根地址改为首页，并下掉首页那张"回到这一页"自指链接

- Status: Done（2026-10-06，同日部署到真机）
- Priority: Medium（需求方当面两问："为什么 `/clocktower` 进去是登录页，而不是变成 `/home` 页" · "`/home` 下面为什么有个『回到这一页』，这个超链接是何意味"）
- Depends on: `done/frontend-path-routing.md`（同一轮体验，跟着路径路由一起收口）

## 要解决的问题

### 1. 打开站点先看到一张登录卡，而不是门厅

上一轮把地址从 `#/play` 换成正常路径时，刻意保留了"空地址 = 说书人端"这条老行为
（当时它是一条硬约束：装置与旧链接都靠它）。于是用户打开 `http://<主机>/clocktower` 看到的
仍然是一张说书人登录卡——**第一次来的人不知道这是什么**，而这正是"首页"当初被加进来的理由，
只是当时没敢动根地址。

### 2. 首页底部那条链接指向它自己

首页最下面有一行 `<a href="/home">回到这一页</a>`：点它的时候人已经在 `/home` 上，
什么也不会发生；而它占的位置像是"返回上一页"或"回首页"的导航，实际两者都不是
（回首页走顶栏的「首页」）。用户当场问了它是什么意思——**一条解释不清的链接就是多余的链接**。

## 决定

- **空地址（根路径）= 首页**；说书人端有了自己的明确地址 `/storyteller`。
  四个面各自的地址：`<前缀>` = 首页 · `<前缀>home` = 首页 · `<前缀>play` = 加入一桌 ·
  `<前缀>storyteller` = 主持一局。
- 旧的井号写法（`#player` / `#/play` / `#/home` / `#/storyteller`）**继续有效**（就地改写到新路径）——
  这一轮改的是"根地址落在哪个面"，不是"旧链接能不能用"。
- 首页那行自指链接**删掉**，连带它的样式；要回首页走顶栏「首页」。

## 连带改了什么

- 装置入口：说书人侧的 `openTableAndHost` 与三处直接打开根地址的地方都改走 `/storyteller`
  （根地址现在是首页，等登录卡会白等满超时）；可用性装置新增"空地址 = 首页"的判据。
- `display/navigation.ts`：不认识的地址**也落到首页**（给门厅比给一张报错式的登录卡好），
  面的后缀表改成反查而不是另写一份 switch。
- `App.vue`：首帧按当前地址画（`routeFromPath(location.pathname)`），否则打开首页会先闪一下说书人面。

## 残余

- **登录后打开根地址只是首页，不直接给"继续主持"捷径**：老用户想回自己那一桌要多点一次顶栏。
  这是刻意的第一版（不发明没被要求的行为）；真觉得绕，再单独做"登录后首页给一张我主持的桌"。
- 首页仍然刻意不列桌（未登录看别人的桌没有意义，D-0027）；要不要给"公开桌列表"是另一件事。
