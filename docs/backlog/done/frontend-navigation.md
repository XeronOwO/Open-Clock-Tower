# 前端导航：首页、身份切换与页面互链

- Status: Done（2026-10-06）
- Priority: High
- Depends on: 无（多桌票的"大厅"部分会用到本票的首页框架）

## 落地结果（2026-10-06）

- `display/navigation.ts`：URL hash → 面（首页 / 玩家端 / 说书人端），四个面 + 两条兼容红线。
- `App.vue`：常驻顶栏（三个面互相可点、当前面高亮、显示"当前位置"）。
- `features/home/HomePanel.vue`：首页说清这是什么、给出两条入口、列出在开的桌。
- **兼容红线**（18 个验收装置与用户手里的链接依赖，写成了用例）：
  ① 容器访问根路径（空 hash）仍必须是说书人端；② `#player` 仍必须进玩家端。
- 真机验证：主装置 289 项全绿；服务器上真浏览器 12 项全过（含首页 → 导航互跳 → 开桌 → 入座闭环）。

## 要解决的问题

现在的前端**没有导航**：`App.vue` 只有 18 行，是一个二选一开关——
URL 带 `#player` 就渲染玩家端，**其余一律渲染说书人端**。

因此：

- 玩家想切到说书人端，只能**手改地址栏**（没有任何按钮或链接）；
- 没有首页：打开根路径直接是"说书人登录页"，访客不知道这里是干什么的、也不知道该点哪里；
- 各面之间互相孤立：账号面板、玩家端、说书人端、复盘之间没有跳转关系；
- 地址结构是"一个 hash 开关"，不是可分享、可回退的位置（发给别人一个链接，对方不知道会落到哪）。

需求方原话（2026-10-06）："你这界面都是孤立的吗？还有什么 `#player`，也没见到切换按钮啊。
界面之间要有跳转啊。"

## 要做成什么样

| 面 | 路径 | 内容 |
|---|---|---|
| 首页 | `#/` | 这是什么 + 账号（注册 / 登录 / 改名）+ 桌列表（多桌落地后） |
| 说书人台 | `#/storyteller` | 现在的说书人面板 |
| 玩家席 | `#/play` | 现在的玩家端 |
| 某一桌 | `#/table/<id>` | 进入指定桌（可分享的链接） |

- 顶栏常驻：品牌 + 当前所在面 + 身份（未登录 / 已登录为谁）+ 去往其他面的入口；
- 玩家端与说书人端**互相可见的跳转**（同一个人的两种身份，不是两个网站）；
- 旧的 `#player` 地址**继续可用**（重定向到新结构），否则现有装置与用户收藏的链接会失效。

## 验收矩阵

| # | 场景 | 期望 | 依据 |
|---|---|---|---|
| 1 | 打开根路径 | 落到首页；能看到"这是什么"与账号入口，不是直接怼一个说书人登录框 | 本票 |
| 2 | 未登录访客 | 能注册；注册后停在首页且是登录态 | D-0021 |
| 3 | 已登录 | 顶栏显示"我是谁"，可从首页进玩家席 / 说书人台 | 本票 |
| 4 | 玩家席 ↔ 说书人台 | 两端各有一个可见入口互相跳转，**不需要手改地址栏** | 本票核心 |
| 5 | 浏览器后退 | 在面之间跳转后按后退，回到上一个面（不是退出整个应用） | 本票 |
| 6 | 旧链接 | `#player` 仍能进入玩家端 | 向后兼容 |
| 7 | 刷新 | 停在当前面，不需要重新导航 | 本票 |
| 8 | 信息隔离 | 玩家席的导航**不泄露**说书人专属信息（不出现桌内幕的入口） | D-0012 |

## 决定与依据

- 不引入前端路由库：这套 SPA 目前只有四个面、没有嵌套路由与守卫需求，
  先用"hash 解析 + 顶栏链接"这一层薄封装（`display/navigation.ts`），
  等真需要参数化路由或守卫时再评估引入——避免为四个面背上一个框架。
- 旧地址保留：18 个验收装置与用户手里的链接都指向 `#player`，擅自改结构等于把它们一起打翻。
