## 复查

**判据**：`git blame` 逐行给出「写入提交日」；一行内出现的每个 `YYYY-MM-DD` 若**晚于**写入提交日，
即为硬矛盾（记录不可能早于书写）。机械扫描覆盖 248 个含 `2026-10-` 的文件：

```powershell
$files = git grep -l -E '2026-10-[0-9]{2}' HEAD -- . | % { $_ -replace '^HEAD:','' }
foreach ($f in $files) {
  foreach ($row in (git blame HEAD --date=format:'%Y-%m-%d' -- "$f")) {
    $m = [regex]::Matches($row, '\d{4}-\d{2}-\d{2}')
    if ($m.Count -ge 2 -and $m[1].Value -gt $m[0].Value) { "$f  $($m[1].Value)  $($m[0].Value)" }
  }
}
```

**扫描结果**：修正前命中 **56 处** → 提交 `b23ac2d` 修正 50 处 → 复扫（HEAD = `b23ac2d`）**只剩 6 处**，
与 C 表的保留项逐一对应（本票叙述 4 处、README 索引 1 处、合成夹具 1 处），无未解释命中。

**归档后口径**：本文件自身的「原记」列按定义继续引用被修正的日期原文，故同一脚本在归档后
（HEAD = `6771d9c`）仍命中 **27 处、全部位于本文件**（C 表第 1 行）；加测试夹具 1 处（C 表第 3 行）
共 **28 处**——README 行已按 C 表改写为不含旧日期的描述。**全仓其余文件零命中。**

**批次头专项**：E14–E34 标题日期与该批次`冻结版本`提交日逐条核对，全部一致（E17 跨午夜：冻结提交在
10-03 01:02、批次头记 10-02，属"按会话起始日记"的既定口径，未改）。

**边界（如实记录）**：

- 本判据只能证明「记录日期不晚于其写入提交」，**不能**证明「记录日期 = 事件发生日」——后者需要逐事件
  的运行时证据，超出本票范围；全仓其余 ~820 处日期（多为百科抓取日期 10-01 / 10-04、裁定日期 10-04）
  在本次扫描中未再命中硬矛盾，未逐条回核事件时刻；
- `AGENTS.local.md` 无 git 历史，按相关提交与票据证据修正（见 C 表下方）；
- 本票的 Done 条目与「原记」列会继续包含 10-05/06 字样——它们是**被修正对象的记录**，不是新的矛盾。

## 决定与依据

- **权威口径 = git 提交时间**（本地 +0800）＋外部锚点：钟楼百科 `Date: Sun, 04 Oct 2026 06:31:46 GMT`
  与提交 `5fc99a3`（10-04 14:22 +0800）相差数分钟，证明机器时钟没有整体漂移，git 时间线可靠；
- **回填到写入提交的本地日期，而不是统一成某一天**：E14/E15/E16 = 10-02、E25 = 10-03、E31/E32 = 10-04；
  同族 10-01/10-02 笔误按同一规则回填；

  E14/E15/E16 分别记 10-04/10-05/10-06），也没有时钟漂移证据，不猜测；
- 原报告的判断句「实际为 2026-10-04」只对 E31/E32 成立；E15/E16/E25 的真实日期见 A 表。
