# 恢复失败后的房间健康位（区分「空账」与「数据丢了」）

- Status: Done
- Priority: Medium
- Depends on: 自动步骤机与操作请求（`done/operation-request-step-machine.md`）

## 要解决的问题

事件流 / 快照恢复失败时房间以**空状态**启动（记 Critical，不静默继续，D-0014 能力 3），
但说书人视图里的"空账"与"这一局还没观测到任何东西"长得一模一样：
说书人分不出"没数据"和"数据丢了"。这是明示的数据损失，却没有出现在数据面上。

## 要做的事

1. 房间健康位（如 `RoomHealth.Degraded` + 原因 + 发生时间）进会话状态，**恢复失败时置位**。
2. 说书人视图暴露该健康位；显式重建成功后清除；重建仍失败时保持置位并更新原因。
3. 玩家视图是否提示"数据异常"要单独决策（涉及公平与信息隔离）：本票先只做说书人侧，
   玩家侧维持现状（不下发）。
4. 日志与测试：损坏载荷 → 视图显示 Degraded + 原因；重建成功 → 清除。
