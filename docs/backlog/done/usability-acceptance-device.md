`node tools/verify-entrance-usability.mjs` → **全部通过（判定 27 项 · 跳过 0）**，退出码 0，整机 16.6s。

正好用满阈值 7——再多的每一步都会被判红。

## 要解决的问题

需求方 2026-10-06 的原话是"要给人玩的，不是到处乱放"。而当时的门禁状态是：

| 已有的证据 | 数量 | 它证明了什么 |
|---|---|---|
| `dotnet test` | 1300 通过 | 规则与协议对不对 |
| 主装置（取证档） | 310 项 | 说书人与玩家**能不能玩完一局** |
| 其余 18 个装置 | —— | 各条角色链路、隔离、重建、重连 |

**没有一条断言在问"第一次打开这个站的人，知不知道该点哪"。** 所以界面把注册表单塞进开桌折叠区、
把桌列表放在登录之前、让用户抄 47 个字符的票据——**装置照样全绿**。这是验收体系的一个洞，
不是某一屏的疏忽。

## 目标形态

新增一个装置（或给现有真机装置加一段），**用全新浏览器上下文 + 全新账号**走"第一次使用"路径，
判据取自"新用户实际会遇到什么"，而不是"DOM 里有没有某个元素"：

1. **未登录时页面上只有一张登录卡**：断言页面上**不存在**桌列表、席位按钮、票据输入框、开桌按钮
   （今天会红：玩家端一进来就是桌列表，说书人端主位是票据框）。
2. **从打开站点到坐下，路径长度可数**：记录"点到第几下才真的坐进一张桌"，超出约定步数即红。
3. **换设备能回来**（今天**必然红**，是本票最要紧的一条）：注册 → 开一桌 → 换一个全新浏览器上下文 →
   只登录同一账号 → **看得到"我主持的桌"并进得去主持台**。今天做不到：说书人票据只在开桌回执里出现一次，
   换设备就回不去（残余已登记在 `in-progress/multi-table-and-account-entry.md`）。
4. **术语人话**：页面上不出现"席位票据 / 连接状态：未连接 / 玩家端 / 说书人端"这类词
   （判据用一张禁词表扫描，与零信任装置的收包扫描同款做法）。
5. **同一浏览器切面不掉登录**：在玩家端登录 → 切到说书人端 → 不用再登（今天是两个网关各登一次）。

前 4 条现在应当**部分或全部为红**——这正是它的价值：**先红后绿**（`docs/evidence/verification.md` §3）。
红了之后由 `entrance-redesign.md` 去修，修完它转绿，从此界面改动必须重跑它。

## 怎么落地

- 复用 `tools/verify-live-open-table.mjs` 的骨架（真浏览器 + 分段 + 探活 + 退出码分档），
  它已经是"打真部署"的那一个；本票可以是它的兄弟装置，也可以是它的新段。
- 禁词扫描用"页面上不该出现的词"清单（与各装置的 `STORYTELLER_LEAK` 同款），**而不是**断言某个中文文案存在——
  文案会改，禁词不会。
- 路径长度用"用户动作次数"计数（点击 / 输入算一步），阈值写进断言详情，便于以后收紧。
