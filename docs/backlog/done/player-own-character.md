# 玩家端「本人角色」出口：本人看得到自己的角色与阵营

- Status: Done（批次 E44，2026-10-05：验收矩阵 4 行**逐行判定全部通过**；投影 / 推送 / 前端 / 门禁
  四层落地，规则口径见 `docs/standard/rulings.md` R-0059）
- Priority: High
- Depends on: 无（契约 / 投影 / 前端三处都是既有面，缺的只是这一条出口）

## 要解决的问题

**玩家在自己的设备上看不到自己是什么角色。** 线下玩法里这由说书人私下发角色牌解决；
线上平台的玩家端（`/#player`）此前**没有任何角色面**——`PlayerViewDto`
（`src/OpenClockTower.Contracts/PlayerViewDto.cs`）里有席位、阶段、挂起请求、自己的信息结果、
白天投影、胜负结论、呆瓜公开选择、席位名、艺术家与博学者的入口、已用尽能力，**唯独没有「我是谁」**。

两个具体后果（本票开工时的实证）：

1. 说书人必须靠平台外的语音把角色逐个念一遍，玩家只能从收到的信息反推自己在演什么；
2. **换角不跟随**：麻脸巫婆换角、方古感染、舞蛇人换手、哲学家代行、理发师互换、集骨者重获之后，
   本人视图不会告诉他手里换成了什么——事件流里有事实，只是没有出口。

这条缺口被三张已完成的票记过，却一直没有自己的票（`done/settlement-engine.md` 残余 3、
`done/character-change-family.md`「本票不扩大投影面」、`done/character-art-hotlink.md`
「玩家端当前没有任何角色面」）；它也直接挡住「整局端到端验收」——玩家不知道自己的角色，
那一局就不是完整的一局。

## 开工前必须先回答（已答，先登记再实现）

1. **本人能不能看到自己的阵营？——能，而且必须。** 平台下发角色时**一并下发阵营**，四个来源：
   百科《认知覆盖》· 能力简介「在《染》中，玩家可以随时向说书人确认自己的当前角色和阵营，
   **且必定会获得正确信息**」；百科《术语汇总》· 阵营「**玩家始终会得知其当前的阵营。**」；
   百科《阵营转变》· 能力简介「阵营发生转变…**第一时间**得知自己的当前阵营」；
   百科《重要细节》· 三-2「角色或阵营发生变化…**第一时间秘密得知**」，且
   「**得知自己的角色或阵营发生变化并不算是获得信息**，因此也不会受到醉酒、中毒或者类似涡流
   这样的角色所影响」。已登记为 `rulings.md` **R-0059**（含首版无认知覆盖角色的论证与偏差登记）。
2. **与「已用尽能力」（`ExhaustedAbilities`）是否合并呈现？——不合并。** 两者是不同的账：
   `ExhaustedAbilities` 回答"我用过哪些每局限一次的能力"（按**席位**记，换角后不跟着走），
   本人角色回答"我现在是谁"（按**角色维度**记，随事件变）。合成一块会在换角之后自相矛盾
   （例如换成贤者却仍列着"艺术家已用尽"）。前端两块分开呈现，字段各自独立。

## 要做的事（定稿）

1. **投影出口**：`PlayerViewDto` / `PlayerView` 各加 `Character`（角色 slug）与 `Alignment`
   （`Alignment` 枚举名）两个**只描述收件人本人**的**标量**；未观测为 null（不猜，D-0015）。
   中文名走既有 `labels` 呈现层（`RosterMirrorGateTests` 对账），不新增第二份花名册。
2. **换角跟随**：`GameNotificationBuilder` 对带 `Character` 或 `Alignment` 的 `SeatStateChangedEvent`
   追加一条**定向**（`Seat` = 变化者）本人视图推送；重连按既有口径从快照拿同一份事实
   （D-0010 / D-0012），不做"本地先跑再跟随"。
3. **前端呈现**：玩家页新增「我的角色」面板（`角色中文名（slug）` + 阵营），
   与帮助条目 `player-character` 一起进 `display/help.ts` 的登记表。
4. **门禁**：`PlayerProjectionLeakGateTests` 补**反方向**断言——本人角色 / 阵营字段必须是标量，
   出现"席位 → 角色"的集合形态即红；说书人的 `SeatCharacterAssignmentDto` 进玩家侧类型名禁列。

## 本批顺带修掉的一处跨票相互作用（装置抓出来的真红）

取证档首跑在 `day1` 段报红：「旅行者阵营不进无关玩家的任何面（善良 / 邪恶 / Good / Evil 零命中）」——
命中的正是本票新增的「我的角色」面板（每个玩家本来就该看到**自己的**阵营，R-0059）。
修法是**收窄断言而不是放宽它**：扫描前把 `[data-testid="player-own-character"]` 从 `.shell` 里
临时摘掉（`display: none` + `try/finally` 还原），剩下的面里出现那四个词才算旅行者阵营越权。
**该断言已被变异验证仍有牙**：在面板之外塞「善良 邪恶」→ 7 席全部变红。
这条记下来是因为它证明"本人角色出口"确实会与既有隔离断言正面相遇，而正确处理是精确化断言。

## 决定与依据

- **规则口径**：`rulings.md` R-0059（含依据 5 条、处理 4 条、偏差登记与"将来纳入认知覆盖角色时
  要改读认知值"的接线说明）。
- **只增两个标量**：不下发"席位 → 角色"的映射（D-0012 §4.3 / D-0013 §5）；
  说书人的分配表 `SeatCharacterAssignmentDto` 仍只说书人可见。
- **推送只认角色 / 阵营两维**：生死 / 醉酒 / 中毒不在本人视图里（夜晚死亡到黎明才公告，R-0022），
  为它们推等于用推送节拍泄露"你身上刚刚发生了事"。
- **不新增信息结果**：这两个字段是**事实**，不产 `InformationResultIssuedEvent`、不经说书人裁定、
  不因醉酒 / 中毒 / 涡流而伪造（百科《重要细节》三-2 明文）。

## 残余与边界（登记，不在本票范围）

1. **玩家侧不接角色图**：本票只做文字面；要接图得先把 `features/grimoire/CharacterArt.vue`
   登记进 `PlayerProjectionLeakGateTests` 的玩家侧依赖清单，另立票（`done/character-art-hotlink.md`
   的接入面结论不变）。
2. **认知覆盖类角色**（酒鬼 / 疯子 / 提线木偶…）不在首版花名册：纳入时本出口要把"账上真实值"
   改成"玩家的**认知值**"，届时投影要读认知层而不是状态账（R-0059「将来接线」）。
3. **白天发生的阵营变化**：平台**即时**下发，而百科《阵营转变》说"说书人在当天夜晚通知"——
   偏差已登记在 R-0059（即时只会更早告诉本人本人的事，不扩大越权面）。
