# 博学者的两条信息：候选事实库 + 说书人辅助排版与自动校验

- Status: Done
- Priority: High
- Depends on: `docs/backlog/done/juggler-and-savant-day-abilities.md`（R-0057 已落地：
  白天命令 → 归属裁定点 → 两条信息只到本人；本票把那个"自由文本裁定框"升级成**结构化辅助面**）

## 要解决的问题

博学者的裁定点现在只给一个自由文本框（两条用 `|` 分隔，R-0057）。说书人要靠记忆现编两条人话，
于是有三个真实问题：

1. **慢**：每条都要自己想措辞、自己确认真假；一局多次出现（每个白天一次）时是持续性负担。
2. **容易错**：平台不判定真假，说书人一旦记错局势（"恶魔在奇数位"其实在偶数位），
   给出的"真信息"实际是假的——这是**平台的记录面在骗人**，比慢更严重。
3. **不会用**：新手说书人不知道该给什么信息，于是永远只给"某某是镇民/爪牙"这类低质量信息。

## 目标（需求方 2026-10-05 当面要求）

- 预置一批**常用在场信息**（不止"奇偶位"）：座位关系、阵营人数、昨晚变化、状态读数、点名类……
- 信息**可组合**（一真一假），所以前端必须**辅助**说书人，而不是把候选平铺成一张大表让他自己挑。
- 带**自动化检查**：组合非法当场拦下并说明原因；真值由平台按账求值，不靠说书人记。
- 提效率、降失误。

## 依据

- 规则：百科《博学者》· 2026-10-01 抓取 · 角色能力 / 角色简介（两条、一真一假、他不知道哪条对哪条、
  可以不问、醉酒中毒时可能两条全对或全错）；平台口径见 `rulings.md` R-0057。
- 现有实现：`SavantQuestionSource`（自由文本 `|` 分隔 + 格式拒绝）、`SavantQuestionMachine`
  （白天一次、未结清挡收口）、玩家投影（两条只到本人、`CanAskSavantQuestion` / `AwaitingSavantQuestion`）。
- 边界：**平台只做记录 + 校验 + 推演**（`AGENTS.md` 第一原则）；本票不改这一条——事实的真值由
  **状态账**求值（可验证、可复现），"给哪两条"仍由说书人拍板；D-0002 的"平台不替说书人编内容"不变，
  变的是**平台把候选与真值摆到他面前**。

## 方案

### 1. 候选事实库（机器可判定的"一句人话"）

每条 = `事实编码 + 参数 + 人话文案 + 真值三态`。真值三态：**真 / 假 / 判不了**（账上没观测齐——
不允许猜；判不了的事实不进候选）。分组与首版清单（结合《梦殒春宵》角色集）：

**A. 座位关系（邪恶怎么坐）**

| 编码 | 事实（人话） | 参数 |
|---|---|---|
| `demon-seat-parity` | 恶魔坐在奇数位（或偶数位） | 奇 / 偶 |
| `demon-minion-distance` | 恶魔与最近的爪牙之间隔着 N 名玩家 | 无（数值由平台算） |
| `minion-next-to-demon` | 恶魔左右相邻的席位里有爪牙 | 无 |
| `minions-adjacent` | 两名爪牙彼此相邻 | 无（爪牙 ≥2 时才有意义） |
| `demon-next-to-outsider` | 恶魔相邻的席位里有外来者 | 无 |
| `demon-flanked-by-townsfolk` | 恶魔两侧最近的镇民之间隔着 N 名非镇民 | 无 |

**B. 阵营与人数（局势）**

| 编码 | 事实 | 参数 |
|---|---|---|
| `evil-not-fewer` | 邪恶阵营的存活人数不少于善良阵营 | 无 |
| `evil-majority` | 邪恶阵营的存活人数多于善良阵营 | 无 |
| `alive-count-parity` | 存活人数是奇数（或偶数） | 奇 / 偶 |
| `alive-count-equals` | 存活人数恰好是 N | 数值 |
| `good-lead` | 善良阵营比邪恶阵营多 N 名存活玩家 | 无 |
| `traveller-present` | 场上有旅行者 | 无 |

**C. 变化（昨晚 / 今天发生了什么）** ← 需求方点名的第二类

| 编码 | 事实 | 参数 |
|---|---|---|
| `character-changed-last-night` | 昨晚有玩家的**角色**发生变化（麻脸巫婆 / 理发师 / 舞蛇人 / 方古） | 无 |
| `alignment-changed-last-night` | 昨晚有玩家的**阵营**发生变化（方古侵染 / 舞蛇人交换） | 无 |
| `character-changed-today` | 今天有玩家的角色发生变化 | 无 |
| `death-last-night` | 昨晚有玩家死亡 | 无 |
| `death-today` | 今天有玩家死亡或被处决 | 无 |
| `execution-happened` | 今天有人被处决（涡流局的胜负条件相关） | 无 |

**D. 状态与能力读数**

| 编码 | 事实 | 参数 |
|---|---|---|
| `poisoned-present` | 场上有玩家中毒 | 无 |
| `drunk-present` | 场上有玩家醉酒 | 无 |
| `demon-impaired` | 恶魔目前醉酒或中毒 | 无 |
| `malfunction-last-night` | 昨晚有玩家的能力未正常生效（与数学家同源读数） | 无 |
| `limited-role-exhausted` | 有角色已经用尽它的限次能力 | 无 |

**E. 点名类（高强度：平台标出来，用不用由说书人）**

| 编码 | 事实 | 参数 |
|---|---|---|
| `seat-is-evil` | N 号玩家是邪恶阵营 | 席位 |
| `seat-character` | N 号玩家的角色是「X」 | 席位 + 角色 |
| `role-in-play` | 角色「X」在场 | 角色 |
| `role-dead` | 角色「X」已经死亡 | 角色 |
| `two-seats-same-team` | N 号与 M 号同阵营 | 两个席位 |

> 清单是首版起步集；新增一条事实 = 一个纯函数（求值 + 文案），不需要动状态机。

### 2. 自动化检查（本票的核心价值）

| # | 检查 | 触发条件 | 结果 |
|---|---|---|---|
| C1 | **一真一假** | 能力**生效** | 两条真值必须恰好一真一假；否则**拒绝**并说明（"两条都为真 / 都为假"） |
| C2 | 允许同真伪 | 能力**未生效**（醉酒 / 中毒 / 死亡） | 放行；提示"可以都给真或都给假" |
| C3 | 涡流在场 | `VortoxInterference.IsActiveFor` | 两条都必须为**假**；否则拒绝（R-0028） |
| C4 | 同事实 / 互为反面 | 任意 | 拒绝（必然同真伪，给不出"一真一假"） |
| C5 | 判不了 | 账上维度没观测齐 | 该事实**不进候选**；客户端硬塞 → 拒绝（不猜，D-0015） |
| C6 | 自填兜底 | 任一条是自由文本 | 不做真值校验，但**显式标注「未校验」**并把原因写进事件 Note |
| C7 | 强度标注 | E 组点名类 | UI 标「高强度」；假信息可任意，真信息必须真——由 C1 兜住 |

真值求值只在**服务端**（前端不判规则，web/AGENTS.md §4）：候选与真值随裁定点提示下发（快照），
**提交时按当时的账重新校验**——挂起期间角色被换走 / 有人死亡时，以提交时刻为准（与"结算取当时账"同姿态）。

### 3. 前端排版（说书人视角，不得平铺成一张大表）

裁定点面板改成 **两个槽位 + 辅助面**：

```text
┌ 能力状态横幅 ────────────────────────────────────────────┐
│ 生效中：必须一真一假            当前组合：一真一假 ✓     │
├ 第一条 ─────────────────────────────────────────────────┤
│ [类别：座位 | 人数 | 变化 | 状态 | 点名]  [搜索…]        │
│  ● 恶魔坐在奇数位            [真]   ← 选中态             │
│  ○ 恶魔与最近的爪牙隔着 1 名玩家 [假]                    │
│  …（按类别分组，常用置顶；点名类带「高强度」标）          │
│ 参数：奇 / 偶   →  将告诉玩家：「恶魔坐在奇数位」         │
├ 第二条 ─────────────────────────────────────────────────┤
│ 同上；组合结论随选择实时更新（都真 / 都假 → 红字 + 原因） │
├ 兜底 ───────────────────────────────────────────────────┤
│ 自己写两条（不校验，风险自负）  [提交]（组合非法时禁用）  │
└─────────────────────────────────────────────────────────┘
```

排版要点（需求方明确要求"不是简单罗列"）：

1. **类别分栏 + 搜索**，不做一条大列表；
2. 每条后面带**真值徽章**（真 / 假）——说书人一眼看出"想要假信息就挑带假徽章的"；
3. 两个槽位各自独立选择，**组合结论条**常驻（实时显示"现在是一真一假 / 都真 / 都假"）；
4. 参数类事实（点名 / 角色 / 数值）在选中后就地展开参数选择，不跳页；
5. 提交按钮在组合非法时**禁用 + 写明原因**（服务端仍会再校验一次）；
6. 保留自由文本兜底入口（旧口径仍受理，标注「未校验」）。

### 4. 记录与投影

- 事件里记**结构化事实**（编码 + 参数 + 求值结论 + 快照序号），人话文案由同一处生成：
  复盘 / 审计能看到"当时这条为什么为真"；玩家端只收到人话文本，**看不到编码与真值**（投影边界）。
- 说书人视图保留完整结构化裁定（含两条的真值与组合结论）。

## 自检表

| 问题 | 结论 |
|---|---|
| 规则依据 | 百科《博学者》两条一真一假；真值求值不改规则，只校验说书人的选择 |
| 平台越界了吗 | 没有：平台**不替**说书人挑信息、不生成内容；只把候选摆出来并核对真值（记录 + 校验 + 推演） |
| 状态属于谁 | 事实真值不落账（是当前账的**函数**）；结构化选择随裁定事件进事件流（可重放） |

| 家族对齐 | 与艺术家（自由文本裁定）、数学家（平台算数字）两族对照；两者的既有口径不变 |
| 结构门禁 | 事实库一文件一类（`SavantFacts`），新增事实只加纯函数；`GameHub` / 相关文件触 600 行门禁时按先例拆 |

## 残余 / 风险

- **清单取舍仍需需求方过一遍**（本票唯一的用户口径待办）：落地后的 28 条事实按"常用度"取，
  请挑出**不常用的删掉、缺的补上**——尤其「昨晚与今天」那一组（7 条），取决于你们实际怎么给信息；
  上面「与草案清单的偏差」表里的改动也请一并确认。删一条 = 删一个 `SavantFactDefinition`，
  不动状态机、不动投影。
- **人话措辞**（已落地，仍可微调）：文案在事实定义里，短句、无歧义（「恶魔坐在奇数位」而不是
  「恶魔席位为奇数」）；玩家看到的就只有这一句。
- **强度平衡不属于平台职责**：E 组只标「高强度」徽章，用不用仍由说书人裁量。
- **「互为反面」的界面预拦**：前端拿不到"互斥组"信息，因此只预拦「同一条事实写两遍」与真值组合；
  「互为反面」（如奇 / 偶两条）由服务端在提交时用可读原因拒绝。若要在界面上也当场禁用，
  得再给候选加一个互斥组字段——需求方要就给。
- 与 R-0057 的兼容：自由文本路径保持受理（老设备 / 老客户端不受影响）；本票只**新增**结构化路径。
- `last-night` 的口径已登记为 **R-0057-C**（最近一个**已结束**的夜晚阶段；
  「变化」要求变化前后都已知；失效类与数学家同一份计数口径）。
