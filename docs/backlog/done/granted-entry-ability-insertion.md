# 非首个夜晚获得的「首个夜晚」能力没有结算位（哲学家 / 集骨者 / 角色变更）

- Status: Done（批次 E39 判出：验收矩阵 12 行全部通过；主装置取证档 293 项全过 / 0 跳过）
- Priority: High
- Depends on: 无（同族票：`done/character-change-family.md`、`done/traveller-and-exile.md`、`done/settlement-engine.md`）

## 要解决的问题

说书人在第三夜让**哲学家**获得钟表匠的能力，或者在黄昏让**集骨者**重获一名已死亡的钟表匠的能力
——按规则，这两名玩家**当晚就会被唤醒并拿到信息**。平台现在什么都不做：

| 路径 | 现在的行为 | 代码点 |
|---|---|---|
| 哲学家获得「首个夜晚」能力（非首夜） | 本格留一条「本格不产生行动」的跳过记录 | `NightPlanBuilder.BuildPhilosopherSlot` 的 `NoActionSlot`（口径 R-0036 第 4 条） |
| 集骨者重获「首个夜晚」能力 | 重获照常落账，但**没有任何槽位**、连跳过记录都没有 | `NightSlotActivation.PlanRegained` 扫不到格就返回 null（口径 R-0054 第 6 条「不造格 / 过时不候」） |
| 角色变更成「首个夜晚」角色（麻脸巫婆 / 理发师 / 舞蛇人） | 同样没有格 | `NightSlotActivation.Plan` 扫不到格就返回 null（`done/character-change-family.md` 行 10 登记为「不在本票范围」） |

**根因**：三条路径本质是同一件事——「在**非首个夜晚**获得一项**进场能力**」；而夜晚顺序表的
「其他夜晚」一段里根本没有这类角色的行动格。平台只会**激活已有格子**（`SlotActivatedEvent`），
不会**追加**一格，于是这三条路径全部无声落地。

这不是"时机差了半拍"，是**整条能力效果丢失**：玩家拿不到信息，说书人也不知道平台为什么不理他。

## 依据（均为百科 · 2026-10-01 / 2026-10-04 抓取）

1. 百科《重要细节》· 七——「如果新的能力原本**只在游戏的首个夜晚**产生效果，那么它会在**角色变化的
   当晚**产生效果。」「如果带有『在你的首个夜晚』角色在**游戏中途被创造**，这些角色会**尽可能快**地
   进行进场能力的效果结算，因为他们的能力不会在夜晚顺序表的『其他夜晚』部分出现。但仍需注意，
   **绝大部分获取信息的能力应该在所有会造成死亡的效果之后结算**。」
2. 百科《获得能力》· 能力简介——「如果玩家获得的能力是一项**进场能力**……如果是在**非首个夜晚**且
   需要唤醒该玩家的（如获取信息、玩家需要做出选择等），那么一般需要在夜晚顺序表中，
   **所有会造成玩家死亡的行动与效果全部结算完毕后，插入结算这些效果，唤醒该玩家并触发相应的能力**。」
   「另外，如果玩家在夜晚时获得进场能力的**时机晚于这一规定时机**，那么这些能力都会
   **立即生效并进行结算**。」
3. 百科《哲学家》· 运作方式 8——「如果这个角色能力是『首个夜晚』能力，他会在**当晚**使用该能力。」
   · 范例 2——「在**第三个夜晚**，哲学家选择获得钟表匠的能力。**当晚**，他得知了恶魔与爪牙之间的最近的距离。」
4. 百科《集骨者》· 角色简介 1——「如果该角色有『在你的首个夜晚』或『每局游戏限一次』的能力——
   比如贞洁者、猎手、**钟表匠**、女裁缝或者杂耍艺人——该玩家可以**在黄昏之前再次使用这些能力**，
   即使先前已经使用过了。」· 范例 4——集骨者恢复杂耍艺人的能力，当晚杂耍艺人得知「3」。
5. 「每局游戏限一次」那一半**已经实现**（有序表内的格 → 激活 + 上限 2，R-0054 第 4 条）；
   本票补的是**「首个夜晚」那一半**——《梦殒春宵》里这类角色只有**钟表匠**（首夜表有、其他夜表没有）。

## 方案

### 1. 内核：槽位追加原语

新增事件 `SlotInsertedEvent { int Index; StepSlot Slot; }` + `SlotInsertionFolder`（与
`SlotActivationFolder` 并列）：

- 只允许**未来位置**（`Index > 当前槽位下标`）：插入点之前的格子已经走过，回填会让历史与投影分叉；
- 插入点 ≤ 当前下标时**下标整体右移**的语义不存在（被上面的前置条件排除），折叠只做"插进去"；
- 槽位标识在同一计划内唯一（复用即抛错，与建表期 `TagOf` 的重复检查同族）；
- 折叠进 `StepMachineFolder` / `GameStateMachine`；复盘目录按 D-0020 认领它
  （`SlotReplayPresenter`：这一格是"某人的能力被追加唤醒"，玩家能在复盘里看到）。

### 2. 规则层：插入位怎么算、槽位怎么造

- **插入位**＝「本夜**最后一条可能致死的行动格**之后」（依据 1 的"所有会造成死亡的效果之后结算"），
  并**封顶到黎明等待格之前**（追加格必须在夜内结算）。
  致死性的首版判据与 R-0030 第 1 条的麻脸巫婆窗口关闭点**共用一处实现**（`NightDeathWindow`）：
  计划里最后一个恶魔角色槽位——首版会造成死亡的夜间行动（恶魔击杀、流莺造访、麻脸巫婆的死亡裁量）
  都不晚于恶魔段；跨剧本扩展时只改那一处。**不另立一套"按能力自声明致死性"的分类**：
  那会与已登记的 R-0030 口径分叉（当初的设计稿写过自声明方案，落地时按共用口径收口）。
- **时机已晚**：若获得发生的那一格已经在插入位之后（例如理发师换角格在恶魔段之后），
  则**紧随当前格之后**追加（依据 2 的"立即生效并进行结算"）。
- **顺序**：同一夜多名持有者时，后追加者**先**唤醒（每格都"紧跟致死段之后"的自然结果）——
  规则原文把顺序交给说书人，平台取这个确定性口径（裁定 R-0055 第 3 条）。
- 槽位形状：`StepSlotKind.Action`；`Owner` ＝ 被获得角色（结算契约的检索键）、
  `Character` ＝ 行动者本人的角色（代行口径见 R-0036）；标识 = `{被获得角色}@{行动者席位}`
  （同一席位同一项能力只有一格）；提示取自被获得角色的契约；
  依赖沿用同族（重获路径不锁生死、代行路径锁本人角色）。
  入格放行由既有的 `StepSlotEntry.UnavailableReason` 兜底（重获窗口终止 / 授予被替换 → 显式跳过）。

### 3. 三条来源都要接上（整族对齐）

| 来源 | 接入点 |
|---|---|
| 哲学家获得 | `PhilosopherNightAction.Resolve` 的授予路径（经 `PlanGranted` 的兜底） |
| 集骨者重获 | `BoneCollectorNightAction.Resolve`（经 `PlanRegained` 的兜底） |
| 角色变更 / 交换 | `NightSlotActivation.Plan`（麻脸巫婆 / 理发师 / 舞蛇人 / 说书人手工上报四处共用） |
| 复活（只改生死、角色不变） | **不追加**：平台分不清"真复活"与"改掉一次报错的死亡"，口径见 R-0055 第 4 条 |

### 4. 裁定与文档同步

- 新增裁定条目（「非首个夜晚获得的『进场能力』的追加结算」），并在 R-0036 第 4 条、
  R-0054 第 6 条挂指针说明**原文口径已被本条取代**（旧条目不改写，只加注，R-维护规则 3）。
- `docs/architecture/current.md` §2.6 补一行（相对顺序表的"追加位"从哪来）。

## 决定与依据

- 插入位取"最后一条可能致死的行动格之后"，而不是"黎明之前"：依据 1 的措辞是
  「尽可能快……但应该在所有会造成死亡的效果之后结算」——位置有下界也有**上界**（尽可能快）。
- 致死性用契约声明而不是按角色类型猜：依据原文说的是"会造成死亡的效果"，
  而"恶魔一定排在最后"只是当前顺序表的偶然。
- 「每局游戏限一次」那一半不动：既有实现已覆盖（R-0052 / R-0054 第 4 条），本票只补首夜能力。
- 不追加的情形写进裁定：本阶段有格（走既有路径）、任何阶段都没有夜间格
  （艺术家 / 博学者一类的白天能力 → 白天入口按 `AbilityPresentOn` 受理）、契约未实现（不造提示）。

## 残余（本票不做，另行登记）

- 「死亡时仍保有能力的例外」不重获（R-0054 第 10 条）：依赖亡骨魔 / 僵怖的夜间契约，见
  `docs/backlog/todo/vigormortis-death-ability-retention.md`。
- 首夜能力被获得的**提示文案**是否要说书人额外说明（《集骨者》规则细节 2：非强制能力无需提示）：
  本票按既有口径只给行动格、不额外造提示。
