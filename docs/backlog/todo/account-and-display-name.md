# 账号与显示名：让局内每个人知道对面是谁

- Status: Todo
- Priority: Medium
- Depends on: 无（M1 显示名可独立落地）；与 `replay-auto-review` 的文案面相关（复盘里的「谁对谁」需要姓名锚点）

## 要解决的问题

现在平台只有**席位号**：玩家端与说书人端一律以 `1..N 号` 称呼玩家。玩家 aaa 坐在 1 号位时，
同桌的其他人（以及说书人）在界面上**看不到「1 号是 aaa」**——只有线下或语音里口头对号，
才能把席位号翻译成人名。后果：

1. 远程 / 网局时，「轮到 3 号做选择」「2 号被提名」「谁在卡着」都无法与具体的人对上；
2. 说书人找人与玩家互相沟通，都要额外维护一份口头映射；
3. 复盘 / 公告 / 提名记录的文案只能写「3 号」，每个人读的时候都要在心里翻译一遍；
4. 没有跨局身份：换一局就是新票据，名字与关系都不累积。

**现状清点**（代码即证据）：

| 位置 | 现状 |
|---|---|
| `src/OpenClockTower.Application/SeatTicket.cs` | 只有 `Seat` + `Ticket`，无姓名 |
| `src/OpenClockTower.Application/GameSetup.cs` | 只有席位票据列表 + `StorytellerTicket`，无姓名 |
| `src/OpenClockTower.Server/GameSetupEntity.cs` | 会话表只有 `SeatsJson` + `StorytellerTicket`，无姓名 |
| `src/OpenClockTower.Server/GameDbContext.cs` | 只有 Events / Snapshots / Receipts / Games 四张表，**没有用户 / 账号表** |
| `src/OpenClockTower.Application/GameSetupFactory.cs` | 票据是 `seat-{n}-{guid}` 随机串（自注「占位实现」），由启动日志打印 |
| `GameHub.JoinSeat(ticket, lastSequence)` | 加入只需要票据，没有姓名入口 |
| `web/src/**` | 没有姓名 / 昵称字段与呈现 |
| `docs/standard/terminology.md` | 还没有「玩家名」这一标识 |

身份系统的边界（`done/zero-trust-security-model.md` + D-0012）：会话票据**只用于定位会话、不用于授权**，
且是一局一次、由服务端生成、从数据库或启动日志取（D-0018）——它**不是账号**：没有注册 / 登录 / 跨局身份。

## 里程碑建议

- **M1 局内显示名**（本票先做）：每个席位有一个**公开的**姓名标签，同桌所有人可见，如「1 号 · aaa」；
- **M2 账号与跨局身份**（范围待定稿）：注册 / 登录 / 跨局身份 / 名字的来源与找回。
  M2 若纳入，需单独立决策并补验收矩阵（见「开工前必须回答」第 4 条）。

## 验收矩阵（M1）

| # | 场景 | 期望 | 证据 |
|---|---|---|---|
| 1 | 设置姓名 | 可为席位设置显示名（谁设置、何时可改由「开工前必须回答」定稿）；服务端一律做有界化（长度 / 字符 / 空白折叠）并拒绝非法输入，非法输入不落状态 | 集成用例 + 前端单测 |
| 2 | 公开可见 | 同桌所有人（含说书人）看到同一份「席位 → 姓名」映射；姓名是公开信息 | 真机装置截图 |
| 3 | 零信任 | 姓名不参与授权与判定：自报 / 伪造姓名不能获得他人权限，姓名缺失不影响任何规则行为 | 零信任装置 + 投影用例 |
| 4 | 重放与恢复 | 姓名可重放：重启 / 重连 / 重建后仍在（承载层级在开工时定稿） | 集成用例 |
| 5 | 呈现一致 | 席位牌 / 提名 / 投票 / 裁定归属 / 复盘使用同一份姓名与同一套拼接口径；未知取值原样回显 | 截图 + 结构审查 |
| 6 | 缺失兼容 | 未设姓名时所有界面退回「N 号」，不破版、不白屏 | 前端单测 |

## 开工前必须回答（实施前定稿并登记决策 / 裁定）

1. **承载层级**：姓名是本局公开事实（进事件流，随 D-0010 重放）还是会话信息（随 `Games` 表）？
   先例：D-0017（角色分配进事件流）、D-0019（注记进事件流 + 独立账）——考量的都是重放 / 重连 / 审计 / 多设备一致；
2. **来源与权限**：玩家加入时自填 / 说书人分配 / 宿主预置？谁能改、什么时候能改（阶段开始后是否锁定）？
3. **唯一性与冒用**：无账号时无法防冒名（姓名只是显示标签）；是否允许重名、是否做冲突提示——
   定稿并写明「姓名不是凭据」；
4. **账号（M2）边界**：完整账号系统是否纳入首版？账号解决「你是谁」、票据解决「你在这一局是谁」，
   两者不得互相取代（D-0012）；若纳入，需单独立决策并写明与 D-0005（规模约束）的关系；
5. **术语**：`docs/standard/terminology.md` 先登记 `display-name`（中文「玩家名」）标识，再落代码与文案。

## 决定与依据

- **本票只登记缺口与验收方向，不实现**：实施前先补齐上面五个问题的定稿。
- 姓名是**公开呈现信息**，不改变任何规则与投影红线（D-0012）：不参与授权、不进 `GameState`、不做规则判定；
  与「公开生死面」（R-0022）不同——生死是游戏事实，姓名是会话事实。
- 与既有票据的关系：`replay-auto-review` 的步骤说明、将来任何「谁对谁」的文案都需要姓名锚点；
  本票的 M1 是那些文案的前置，但两者可以独立推进。
