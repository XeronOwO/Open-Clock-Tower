# 钟盘投票形态：设计与实现（R-0017 目标形态）

- Status: Todo
- Priority: Medium
- Depends on: `docs/standard/rulings.md` R-0017（2026-10-04 需求方口径）；AGENTS.md 内核确定性硬约束

## 要解决的问题

R-0017 现有实现是「投票开放窗口 + 说书人计票快照」。需求方 2026-10-04 给出**目标形态**：

- 提名时：蓝色时针指向提名者、红色分针指向被提名者（钟盘意象）；
- 双方发言结束后：说书人点「开始」→ 倒计时（默认 3 秒，可调）→ 分针旋转逐席收票
  （间隔默认 1 秒，可调）；
- 玩家在分针指向自己时完成表态（举手 = 投这一票）；
- 票面与结果按线下「绕圈点数」的等价语义。

本票把它设计与落地；落地前 R-0017 保持 `Open`（现行默认口径仍有效）。

## 开工前必须回答

1. **内核确定性**：倒计时 / 旋转间隔是真实时间——不得进入内核判定。方案倾向：节奏在控制面 / 呈现层，
   内核只收显式事件（如「进入第 N 席收票」「第 N 席举手 = 是 / 否」由服务端或说书人推进），
   保证回放与重连可复现（D-0010 / D-0015）。
2. **逐席收票的举手语义**：分针指向某席时读「该席当前举手状态」（线下等价：先举也算、过时不候），
   还是给该席一个反应窗口（容忍网络延迟）？两者事件形态不同，开工时定稿。
3. **参数归属**：倒计时 / 间隔默认 3s / 1s、可调——配置存在哪（会话级？事件流里记显式输入？），
   是否影响判定（不应影响），重连后如何恢复。
4. **与现状的关系**：替换现有「投票窗口 + 计票快照」（同一功能的形态升级），还是保留两种模式？
   倾向替换（另立模式会让投影与装置分叉）。
5. **投影与公开面**：分针旋转期间谁可见什么（R-0017 第 5 条公开面在新形态下的等价物）；
   死亡玩家的票如何消耗；提名 / 投票的撤销语义。
