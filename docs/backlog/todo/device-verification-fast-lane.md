# 装置验证快通道：分段选择器 + 断言从花名册派生

- Status: Todo
- Priority: Medium
- 来源：2026-10-04 用户当场指出的效率问题（本轮主装置连跑 3 次，单次 210–314 秒）

## 要解决的问题

装置（`tools/verify-storyteller-panel.mjs`、`tools/verify-winloss.mjs` 等）现在是**单体**的：
一次运行 = 一次 Release 构建 + 宿主机 + Vite 冷启 + 每席一个浏览器上下文 + 把 100+ 条断言全跑完。
于是"改一行夹具 / 改一处断言"的验证成本被固定开销支配，形成"改一行、跑 3 分钟"的循环；
本轮为收敛一个夹具假设连跑 3 次，其中至少一次是"改完就整跑、没先读断言"的纯浪费。

`AGENTS.local.md` 的「验证成本纪律」只能提醒（规则不阻断），**根因是缺少比整装置更顺手的路径**。

## 验收矩阵

| # | 行 | 判据 |
|---|---|---|
| 1 | 分段选择器 | `--only <section>`（可重复）/ `--from <section>` 只跑指定段落；段落名在用法头与运行时输出里可见 |
| 2 | 快通道 | 主装置支持 `--skip-build`（复用 Release 产物）与 `--no-screenshots`（跳过 PNG 落盘，且"截图已落盘"那条断言随之跳过而不是误红） |
| 3 | 断言从花名册派生 | 断言里不再出现"合法选项 2 个""三席"这类硬编码席位假设；改花名册不再一次打翻多条断言 |
| 4 | 可量化 | 同一段落在快通道下的单次耗时记录进票据（目标：分段迭代 < 60 秒） |

## 决定与依据

- 装置是**验收**工具（`docs/acceptance/AGENTS.md`：一批 = 一次构建 + 一次多客户端会话），
  不是调试工具；本票把"调试回路"从装置里剥出来，而不是削弱装置的验收强度；
- 快通道参数只影响取证开销，不改断言语义；正式取证仍用默认参数跑全量；
- 与 `docs/evidence/delivery-checklist.md` 的"一次真实运行"要求不冲突：分段跑不作为交付证据。

## 残余

- `tools/verify-winloss.mjs` 已有快通道（117 秒 → 24.7 秒），但**分段选择器与花名册派生断言尚未做**；
- 其余装置（`verify-madness.mjs` / `verify-witch.mjs` / `verify-zero-trust.mjs`）同样没有快通道。
