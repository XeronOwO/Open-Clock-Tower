# 入场重做：账号是唯一身份证，票据退回兜底

- Status: Todo
- Priority: **High**（本票是需求方连问三次指向的同一个域）
- Depends on: 无（D-0021 账号与 D-0026 开桌已落地，本票在它们之上重排）

## 要解决的问题

需求方 2026-10-06 当面连问三次，三条都落在同一个域上——**"你是谁 → 进哪张桌 → 干什么"从来没有被整体设计过**，
它是长了四回长出来的：票据制（那时没有账号）→ 账号贴在票据旁边 → 大厅贴在账号旁边 →
上一轮又把"开桌"塞进登录页的折叠区。每一回都只加一层。

| # | 症状（用户视角） | 现在是什么样 |
|---|---|---|
| 1 | "没有个像样的注册登录界面逻辑，全是到处硬塞" | 注册 / 登录面板被**复制到玩家端与说书人端两处**，各自 `new AccountGateway()`；同一个浏览器里切一下导航就要**再登一次**。两处都把账号表单与桌列表、票据输入、开桌表单平铺在同一张卡片里，用户看不出该先做哪一步 |
| 2 | "说书人票据又是什么东西，不是有账号系统吗" | 说书人票据来自**第一版**（那时票据就是唯一身份）。D-0025 只把**玩家的席位票据**降级了，说书人票据原封不动。今天它的全部作用是让用户抄一串 47 个字符；换台设备或清缓存，那张桌就再也进不去 |
| 3 | "这主界面怎么这么反人类" | 玩家端一进来先给桌列表让你点席位（还没登录），往下才是"也可以凭票据加入"，最底下才是"账号（**可选**）"——顺序把"先有人、再有桌"倒过来了；说书人端主位是票据输入框，底下的开桌折叠区一展开，账号资料、改名、登出、恢复码、桌名、席位数全糊在一起 |
| 4 | 术语 | "玩家端 / 说书人端 / 席位票据 / 连接状态：未连接"——全是给开发者看的 |

## 目标形态

**账号是唯一的身份证；票据退回兜底，不再是任何主路径。**

| 步骤 | 现在 | 目标 |
|---|---|---|
| 打开站点 | 直接进说书人登录框（票据输入框占主位） | 首页：这是什么 + 两个入口「加入一桌」「主持一局」 |
| 没登录 | 账号表单塞在桌列表 / 开桌折叠区里，还写着"可选" | **只显示一张登录 / 注册卡**，没有别的东西 |
| 登录后（玩家） | 桌列表 + 席位 + 票据输入 + 账号表单平铺 | 桌列表 + 选席位 |
| 登录后（说书人） | 票据输入框 + 折叠的开桌区 | **「我主持的桌」列表** + 「开一桌」 |
| 换设备 / 清缓存 | 票据丢了 = 那张桌再也进不去 | 登录同一账号，桌还在那儿 |
| 界面文案 | 玩家端 / 说书人端 / 席位票据 | 加入一桌 / 主持一局 / 邀请码 |
| 登录状态 | 两个端各持一份，切面即丢 | **一份**（跨面共享，账号连接也只有一条） |

票据**不废除**，但只出现在两个折叠入口里：给没有账号的人兜底、以及把桌暂时交给别人（D-0026 的口径不变：
平台不禁止转手，但也不要求转手）。

## 这件事要动什么

### 1) 后端：桌要记住是谁开的

- `Games` 表加 `CreatedByAccountId`（可空，老库靠既有的**加列守卫**原地 `ADD COLUMN`，不换库）。
- `LobbyService.CreateAsync` 落这一列；`GameSetup` / `IGameCatalog` 跟着带上。
- 新增"凭账号进主持台"的入口（`JoinStorytellerWithAccount(accountSession)`，与既有的
  `JoinSeatWithAccount` 同一个形状），并且**只认开桌人**——票据那条路原样保留。
- 大厅列表可选带上"这张桌是不是我开的"，供界面直接用（避免前端自己拼事实）。

### 2) 前端：一个界面一件事

- 账号会话收成**一份**（模块级单例或 `provide`），玩家端与说书人端共用；账号连接只一条。
- 未登录时的**门**：一张登录 / 注册卡（两个 tab + "忘记口令"折叠），没有桌列表、没有票据、没有开桌。
- 登录后的**分流**：玩家 = 桌列表 + 选席；说书人 = 我主持的桌 + 开一桌。
- 票据入口降级成折叠的一行（"有邀请码？"）。
- 文案人话化；删掉所有重复提示（说书人端现在同一条"已开桌"印两遍）。
- 恢复码：显示一次 + 一个"我已抄下"确认，不再和桌名输入框挤在一起。

### 3) 决策与术语

- 需要登记一条新决策（**D-0027：桌归属开桌账号，票据降为兜底**），并在 D-0026 的相关段落标注
  "票据不再是进主持台的唯一路径"——D-0026 的其余口径（说书人是角色、开桌不要求权限）不变。
- `docs/standard/terminology.md` 补「进场 / 我的桌」这类词，并把面向用户的旧称标注为界面不再使用。

## 验收（这一票要能证明"新用户走得通"）

判据不是"界面变好看了"，而是这几条**运行时**断言：

1. 未登录打开站点：页面上**没有**桌列表、没有票据输入、没有开桌按钮（只有登录卡）。
2. 新账号注册 → 开一桌 → **换一个全新的浏览器上下文**（= 换设备）→ 只登录同一账号 →
   **看到"我主持的桌"里有它，点一下进得去主持台**（今天这条做不到：票据丢了就回不去）。
3. 同一个浏览器里：在玩家端登录 → 切到说书人端 → **不需要再登一次**，账号摘要与"我的桌"直接可用。
4. 票据路径仍在：拿票据仍能进主持台（兜底不回退，D-0026 的老断言照跑）。
5. 既有 18 个装置的锚点与红线不变（`player-seat` / `account-*` / 空地址仍是说书人端 / `#player` 仍是玩家端）。

## 残余（本票不覆盖，各自单独排）

- **桌转让**（把主持权交给另一个账号）：先不做，票据仍可临时转手。
- **游客主持**（没有账号也能开一桌）：D-0025 之后玩家必须登录，本票不把游客放回主路径。
- 手机端布局未验证（沿用既有残余）。
