# 入场重做：账号是唯一身份证，票据退回兜底

- Status: Todo
- Priority: **High**（本票是需求方连问三次指向的同一个域）
- Depends on: 无（D-0021 账号与 D-0026 开桌已落地，本票在它们之上重排）

## 要解决的问题

需求方 2026-10-06 当面连问三次，三条都落在同一个域上——**"你是谁 → 进哪张桌 → 干什么"从来没有被整体设计过**，
它是长了四回长出来的：票据制（那时没有账号）→ 账号贴在票据旁边 → 大厅贴在账号旁边 →
上一轮又把"开桌"塞进登录页的折叠区。每一回都只加一层。

| # | 症状（用户视角） | 现在是什么样 |
|---|---|---|
| 1 | "没有个像样的注册登录界面逻辑，全是到处硬塞" | 注册 / 登录面板被**复制到玩家端与说书人端两处**，各自 `new AccountGateway()`；同一个浏览器里切一下导航就要**再登一次**。两处都把账号表单与桌列表、票据输入、开桌表单平铺在同一张卡片里，用户看不出该先做哪一步 |
| 2 | "说书人票据又是什么东西，不是有账号系统吗" | 说书人票据来自**第一版**（那时票据就是唯一身份）。D-0025 只把**玩家的席位票据**降级了，说书人票据原封不动。今天它的全部作用是让用户抄一串 47 个字符；换台设备或清缓存，那张桌就再也进不去 |
| 3 | "这主界面怎么这么反人类" | 玩家端一进来先给桌列表让你点席位（还没登录），往下才是"也可以凭票据加入"，最底下才是"账号（**可选**）"——顺序把"先有人、再有桌"倒过来了；说书人端主位是票据输入框，底下的开桌折叠区一展开，账号资料、改名、登出、恢复码、桌名、席位数全糊在一起 |
| 4 | 术语 | "玩家端 / 说书人端 / 席位票据 / 连接状态：未连接"——全是给开发者看的 |

## 目标形态

**账号是唯一的身份证；票据退回兜底，不再是任何主路径。**

| 步骤 | 现在 | 目标 |
|---|---|---|
| 打开站点 | 直接进说书人登录框（票据输入框占主位） | 首页：这是什么 + 两个入口「加入一桌」「主持一局」 |
| 没登录 | 账号表单塞在桌列表 / 开桌折叠区里，还写着"可选" | **只显示一张登录 / 注册卡**，没有别的东西 |
| 登录后（玩家） | 桌列表 + 席位 + 票据输入 + 账号表单平铺 | 桌列表 + 选席位 |
| 登录后（说书人） | 票据输入框 + 折叠的开桌区 | **「我主持的桌」列表** + 「开一桌」 |
| 换设备 / 清缓存 | 票据丢了 = 那张桌再也进不去 | 登录同一账号，桌还在那儿 |
| 换人主持 | 把票据抄给他 | **不做**：说书人 = 房主 = 开桌账号，本票不提供转让（需求方 2026-10-06 明确"暂时不做身份交接支持"） |
| 界面文案 | 玩家端 / 说书人端 / 席位票据 | 加入一桌 / 主持一局 / 邀请码 |
| 登录状态 | 两个端各持一份，切面即丢 | **一份**（跨面共享，账号连接也只有一条） |

**说书人 = 房主 = 开桌的那个账号，三者等同**（需求方 2026-10-06 补充的口径）。开桌即成为该桌说书人，
凭账号进主持台；**不做身份交接**——不提供"把主持权 / 房主转给另一个账号"的功能。

**票据整个退场，不是降级**（需求方 2026-10-06 追问"为什么还有票据啊"）。有账号系统就不该再有一串
要人抄的凭据。这比"把输入框藏起来"深得多，有两件绕不开的事：

1. **说书人票据（`Games.StorytellerTicket`）与它的入口（`JoinStoryteller(ticket)`）删除**——
   主持台只认"你是不是这张桌的开桌账号"。
2. **默认桌取消**。`default` 桌由启动引导创建、**没有开桌账号**，先天与"说书人即房主"不相容。
   部署完打开站点 = 空大厅，谁想玩谁开一桌。`GameServer:GameId` 这个配置项随之退场；
   连接不声明桌标识时不再"回落到默认桌"，而是显式被拒（现在这条回落是给老客户端留的，
   它同时也是"一张没有房主的桌"的来源）。

## 这件事要动什么

### 1) 后端：桌要记住是谁开的

- `Games` 表加 `CreatedByAccountId`（老库靠既有的**加列守卫**原地 `ADD COLUMN`，不换库）。
- `LobbyService.CreateAsync` 落这一列；`GameSetup` / `IGameCatalog` 跟着带上。
- **删掉 `JoinStoryteller(ticket)`，换成 `JoinStorytellerWithAccount(accountSession)`**
  （与既有的 `JoinSeatWithAccount` 同一个形状），并且**只认开桌人**——这是进主持台的唯一路径。
- **开桌回执删掉 `StorytellerTicket` 字段**（不是"不下发"，是字段没了）；`Games.StorytellerTicket`
  列与 `GameSetup.StorytellerTicket` 一并退场。
- **默认桌与它的回落路径退场**：`GameServer:GameId` 配置项、`GameId` 单例注入、
  `GameBootstrapHostedService` 里的建默认桌、"连接未声明 `?gameId=` 就回落默认桌"这四处一起删——
  留任何一处都会留下"没有房主的桌"。
- 大厅列表带上"这张桌是不是我开的"，供界面直接用（避免前端自己拼事实）。

### 2) 前端：一个界面一件事

- 账号会话收成**一份**（模块级单例或 `provide`），玩家端与说书人端共用；账号连接只一条。
- 未登录时的**门**：一张登录 / 注册卡（两个 tab + "忘记口令"折叠），没有桌列表、没有票据、没有开桌。
- 登录后的**分流**：玩家 = 桌列表 + 选席；说书人 = 我主持的桌 + 开一桌。
- 界面上**没有**票据 / 邀请码入口——本票把它整个删掉，不是折叠起来藏一下。
- 文案人话化；删掉所有重复提示（说书人端现在同一条"已开桌"印两遍）。
- 恢复码：显示一次 + 一个"我已抄下"确认，不再和桌名输入框挤在一起。

### 3) 决策与术语

- 需要登记一条新决策（**D-0027：说书人即房主——桌归属开桌账号，不做身份交接**）。
  它同时**修订 D-0026 里"说书人随时可以把票据交给别人主持"那句**：说书人仍是"玩这一局的角色"
  （不是系统权限，开桌仍不要求任何身份），但**这张桌的主持权归属开桌账号，平台不提供转交**。
  修订要落在 D-0026 的对应段落上（标 Superseded / 加一行"由 D-0027 收窄"），不要只在 D-0027 里说。
- `docs/standard/terminology.md` 补「进场 / 我的桌」这类词，并把面向用户的旧称（玩家端 / 说书人端 /
  席位票据 / 说书人票据）标注为**已从界面与协议退场**。

### 4) 代价：装置与测试夹具要跟着改（本票最贵的部分）

`web/AGENTS.md` §3.1 把"从 `Games.StorytellerTicket` 读票据"写成了装置的**外部耦合**——
19 个装置里凡是需要说书人身份的**都靠它**（直读 SQLite 拿票据 → `JoinStoryteller`），
`TestServerHost.ConnectStorytellerAsync` 也一样。票据一删，这些全部要换路径：

- `TestServerHost`：建桌时显式指定房主账号，再用那个账号的会话进主持台
  （这比"从库里读票据"更贴近真实用法，也是这次改造想要的姿态）。
- 各装置：从"读库拿票据"改成"用夹具账号登录 / 用宿主注入的账号会话"。
- 集成测试里所有 `JoinStoryteller(setup.StorytellerTicket)` 与对 `setup.StorytellerTicket` 的断言同理。
- `web/AGENTS.md` §3.1 的外部耦合表里那一行要跟着改（它现在写着装置依赖 `StorytellerTicket` 列）。

**这一节要在动产品代码之前先改完并跑绿**——它是前置，不是收尾。

## 验收（这一票要能证明"新用户走得通"）

判据不是"界面变好看了"，而是这几条**运行时**断言：

1. 未登录打开站点：页面上**没有**桌列表、没有票据输入、没有开桌按钮（只有登录卡）。
2. 新账号注册 → 开一桌 → **换一个全新的浏览器上下文**（= 换设备）→ 只登录同一账号 →
   **看到"我主持的桌"里有它，点一下进得去主持台**（今天这条做不到：票据丢了就回不去）。
3. 同一个浏览器里：在玩家端登录 → 切到说书人端 → **不需要再登一次**，账号摘要与"我的桌"直接可用。
4. **票据在界面上与协议里都不存在**：容器初始页面、开桌回执、主持台入口三处都扫不到票据 / 邀请码；
   旧协议直调 `JoinStoryteller(ticket)` 被**显式拒绝**（不是静默失效，也不是留着不宣传）。
5. **没有"没有房主的桌"**：全新部署打开站点是空大厅；连接不声明桌标识时被显式拒绝，不再回落默认桌。
6. 既有装置的锚点与红线不变（`player-seat` / `account-*` / **空地址仍是说书人端** / **`#player` 仍是玩家端**）
   ——后两条是**路由面**的事，与"默认桌退场"不冲突。

## 残余（本票不覆盖，各自单独排）

- **桌转让**（把主持权 / 房主交给另一个账号）：**不做**——需求方 2026-10-06 明确"暂时不做身份交接支持"。
  将来真要做的话是一张新票：那时才需要"把房主改成谁"的界面与授权，也才需要重新讨论票据的定位。
- **游客主持**（没有账号也能开一桌）：D-0025 之后玩家必须登录，本票不把游客放回主路径。
- **席位票据**（`Games.SeatsJson` 里每人一份的入座凭据）：本票**先不动它**，但把它从界面主路径撤下
  （玩家登录后从大厅选席）。它要不要跟着整个退场，取决于"游客还能不能入座"这个产品问题
  ——那是另一张票，不该在这张票里捎带决定（用户 2026-10-06 问的是说书人票据）。
- 手机端布局未验证（沿用既有残余）。
