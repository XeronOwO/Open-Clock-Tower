# 玩家端没有「本人角色」出口

- Status: Todo
- Priority: High
- Depends on: 无（契约 / 投影 / 前端三处都是既有面，缺的只是这一条出口）

## 要解决的问题

**玩家在自己的设备上看不到自己是什么角色。** 线下玩法里这由说书人私下发角色牌解决；
线上平台的玩家端（`/#player`）至今**没有任何角色面**——`PlayerViewDto`
（`src/OpenClockTower.Contracts/PlayerViewDto.cs`）里有席位、阶段、挂起请求、自己的信息结果、
白天投影、胜负结论、呆瓜公开选择、席位名、艺术家与博学者的入口、已用尽能力，
**唯独没有「我是谁」**。

两个具体后果：

1. 说书人必须靠平台外的语音把角色逐个念一遍，玩家只能从收到的信息反推自己在演什么；
2. **换角不跟随**：麻脸巫婆换角、方古感染、舞蛇人换手、哲学家代行、理发师互换、集骨者重获之后，
   本人视图不会告诉他手里换成了什么——而这六条路径都已落地，事件流里有事实，只是没有出口。

这条缺口被三张已完成的票记过，却一直没有自己的票（这正是"残余事项不许消失"要防的形态）：
`done/settlement-engine.md` 残余 3（「随玩家端票据」，而那张票据不存在）、
`done/character-change-family.md`（「玩家投影的角色出口是既有残余，本票不扩大投影面」）、
`done/character-art-hotlink.md`（「玩家端当前没有任何角色面（own character 不下发）」）。

它也会直接挡住「整局端到端验收」：玩家端不知道自己的角色，那一局就不是完整的一局。

## 要做的事（草案，立项时按验收矩阵定稿）

1. **投影出口**：`PlayerViewDto` 增加本席角色（slug；中文名走既有 `labels` 呈现层），
   按收件人投影——**只给本人**，不泄漏他人角色（D-0012 §4.3 / D-0013 §5）；
2. **换角跟随**：上述六条角色变更路径之后本人视图跟着变；重连按既有口径补齐同一份事实
   （D-0010 / D-0012），不做"本地先跑再跟随"；
3. **前端呈现**：玩家端显示自己的角色（以及**是否显示阵营**——见下，先登记再实现）；
4. **门禁**：`PlayerProjectionLeakGateTests` 补**反方向**断言——无关席位拿不到本席角色字段。

## 开工前必须先回答

1. **本人能不能看到自己的阵营？** 线下是发牌时同时告知；线上是否随角色一并下发，
   必须先按百科《规则概要》与术语表口径核对并登记 `docs/standard/rulings.md`，
   **不许凭常识写**（`AGENTS.md` 第一原则）。
2. 角色出口与「已用尽能力」（`ExhaustedAbilities`）是否合并呈现——后者已经隐含了本人角色，
   两者的信息面是否应当一致，需要一次投影边界复核。

## 决定与依据

- 信息隔离：`docs/decisions/active.md` D-0012 §4.3、D-0013 §5；
- 角色分配的载体是事件流：D-0017（本票只加出口，不改载体）；
- 角色名与中文名的权威落点：`SectsAndVioletsRoster`（服务端），前端只做呈现副本
  （`RosterMirrorGateTests` 对账）。
