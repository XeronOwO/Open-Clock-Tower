# 席位票据的界面入口：游客还要不要入座

- Status: Todo
- Priority: Medium（产品问题，不是缺陷；入场重做把它的入口撤掉了，得有个了断）
- Depends on: 无

## 要解决的问题

入场重做（E48）把玩家面的**席位票据输入框整个撤掉**了：未登录只剩一张登录卡（那条是入场票的硬判据），
登录之后的主路径是"从大厅挑一个空席位"。于是**没有账号的游客在界面上没有入口**——
协议与票据本身都还在（`JoinSeat(ticket)` / `JoinSeatWithAccount(ticket, session)` 一字未动），
只是界面上不再有人能出示它。

这不是疏忽，是**刻意留白**：需求方 2026-10-06 问的是说书人票据（已整个删除，D-0027），
席位票据绑在另一个问题上——**游客还能不能入座**——那是产品决定，不该在重做里捎带拍板。

今天界面上唯一还在用席位凭据的地方是**登录之后**的兜底路「有邀请码？」（`seat-invite`，
码是 `桌标识:席位票据`）：它是给"这一桌已开局、大厅点不动"的场合准备的（中途到场的旅行者）。

## 目标形态（二选一，需求方定）

| 选项 | 形态 | 代价 |
|---|---|---|
| A. 给游客一个入口 | 首页或未登录的玩家面留一个"我有邀请码"入口，走游客票据路径入座 | 未登录页面上会多一件东西——与入场票"未登录只有一张登录卡"的判据冲突，得先改那条判据并说清为什么 |
| B. 席位票据正式退场 | 删掉 `Games.SeatsJson` 与 `JoinSeat(ticket)`，入座一律要账号 | 旅行者中途到场也必须有账号（今天已经如此）；"换设备兜底"改由账号 + `MySeatNumbers` 承担（已就绪） |

## 现状事实（复核过）

- 服务端：席位票据在会话目录里（`Games.SeatsJson`），说书人加入旅行者时签发（`TravellerSeatIssuer`），
  玩家凭它认领席位（`SeatJoinCoordinator.JoinAsync`）。
- 界面：未登录 = 登录卡；登录后 = 大厅选席 + 「有邀请码？」兜底（`PlayerPanel.vue`）。
- 装置：仍读 `Games.SeatsJson`（`tools/lib/entrance.mjs` 的 `readSeatTickets`），
  但**只有"大厅点不动"的场合才把票据填进界面**（旅行者中途入座）；主路径是账号。

## 验收（哪条都行，但要有判据）

- A：一条运行时判据——游客（无账号）能从界面入座，且入场票的"未登录只有登录卡"判据**同步修订**。
- B：`Games.SeatsJson` 与 `JoinSeat(ticket)` 删除，装置与集成测试全部改走账号；
  `verify-accounts.mjs` 的"凭邀请码坐 3 号"那一段改成"登录后从大厅选席"。
