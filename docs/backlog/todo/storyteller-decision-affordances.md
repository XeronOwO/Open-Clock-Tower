# 说书人面板：裁定归属与读数越界

- Status: Todo
- Priority: Medium
- Depends on: 无（纯 `web/` 呈现层；服务端投影如需补字段，必须先过 D-0012 信息隔离检查）
- 来源：死亡触发族批次装置 `tools/verify-death-triggers.mjs` 的产品侧疑点（本轮记录）

## 要解决的问题

死亡触发族批次在真机上暴露三处说书人体验缺口：

1. **触发格 / 触发型裁定在圆环上没有席位归属**：`decisionSeatOf` = `currentSlotActor ?? stepDigest?.seat`，
   而触发格（`StepSlot.Trigger`）没有 `Actor`、非行动槽位的 `stepDigest.seat` 为 null，
   触发型裁定（如心上人）更是没有槽位——于是圆环既没有「待裁定」chip、也没有「定位到 N 号」按钮。
   实测：贤者的展示裁定明明归属 2 号，说书人看不出"谁在等"（E24 装置截图 `deathtrigger-04`）。
2. **白天计划收口后读数越界**：白天只有 1 个槽位，走完后 `slotIndex + 1 > slotCount`，
   状态条与环心显示「槽位 2 / 1」「第 2 / 1 步」（E24 装置截图 `deathtrigger-02/03` 可见；
   触发型裁定挂起会让这个窗口停留更久，因而更容易被看到）。
3. **裁定候选不区分生死**：心上人的醉酒候选允许已死亡玩家（R-0039 第 3 条口径本身允许），
   但界面没有任何标注，说书人只能靠席位牌回忆谁死谁活（装置候选含已死亡的心上人自己）。

## 验收矩阵

| # | 场景 | 期望 | 证据 |
|---|---|---|---|
| 1 | 触发格裁定（贤者展示） | 圆环标出归属席位 + 「定位到 N 号」按钮出现 | 装置截图逐张复核 |
| 2 | 触发型裁定（心上人） | 归属席位的呈现口径明确（服务端投影「裁定归属席位」或前端按事实推算，二选一并写清） | 结构审查 + 截图 |
| 3 | 白天计划收口 | 读数不再越界（显示「已完成」/封顶为 1 / 1），不再出现 2 / 1 | 截图 |
| 4 | 候选生死标注 | 已死亡候选加「已死亡」标注；不影响服务端候选集合（R-0039 不变） | 截图 + 前端单测（标注映射） |
| 5 | 信息隔离回归 | 归属 / 标注字段不进玩家投影（D-0012）；零信任装置全过 | `tools/verify-zero-trust.mjs` + 投影用例 |

## 决定与依据

- 纯呈现层：不改规则、不改候选集合、不改投影白名单；「归属席位」若需服务端补字段，
  必须先过 D-0012 的信息隔离检查（只说书人可见）。
- 口径以 `docs/standard/rulings.md` R-0038 / R-0039 与 `docs/architecture/storyteller-presentation.md` 为准；
  新词先进 `docs/standard/terminology.md`。
- 与本轮交接建议的「限一次 / 本夜推演常驻显示」面板迭代同批做更省——三者共享
  `StorytellerViewDto` 的投影面。
