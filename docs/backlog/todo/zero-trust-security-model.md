# 零信任安全模型：鉴权、命令校验与信息隔离

- Status: Todo
- Priority: High
- Depends on: 建解决方案、项目骨架与门禁工程

## 要解决的问题

现在没有任何鉴权与命令校验。对于《血染钟楼》这类**信息本身就是胜负**的游戏，
一个能被客户端篡改的服务等于没做：

- 玩家可以伪造"我是 N 号"直接读别人的牌；
- 玩家可以在不该行动的阶段提交行动；
- 玩家可以提交一个根本不合法的选项（比如让僧侣保护自己）；
- 玩家可以把自己的视角"升级"成说书人视角，一眼看穿全场。

需求方明确：虽然是私下里的小服务，**也要做好鉴权、对客户端零信任**。

## 要做的事

1. **两级凭据**（`docs/architecture/current.md` §4.1）：
   `SessionTicket`（整局身份）+ `ConnectionCredential`（绑定到下发它的那条连接，重连重新出示）。
   票据只用于**定位会话**，不用于**授权**——每次请求都按当前状态重新判定权限。
2. **四道闸**中间件/管线（§4.2）：身份 → 阶段 → 合法性 → 幂等。
   任何一闸不过：**拒绝 + 记录 + 不改状态**；拒绝日志带上下文（谁、哪一闸、什么输入）。
3. **信息隔离在服务端投影强制**（§4.3）：一个事件流，按接收者产出说书人视图 / 各玩家视图；
   越权资料**根本不下发**。
4. **前端防御性渲染**（§4.4）：把服务端数据当不可信输入，长度/类型/范围都处理。
5. **负向测试套件**（本票据的重点，见验收矩阵）：不是测"正常能进"，而是测**"越权进不来"**。

## 验收矩阵

| # | 场景（攻击者视角） | 期望 | 依据 |
|---|---|---|---|
| 1 | 用 2 号的票据请求 3 号的私有视图 | **拒绝**，不泄露任何字段 | D-0012 §4.3 |
| 2 | 不持票据直接连 Hub 订阅房间 | **拒绝** | D-0012 §4.1 |
| 3 | 持旧连接的凭据在新连接上重连 | **拒绝**，要求重新出示票据 | D-0012 §4.1 |
| 4 | 玩家伪造 `playerId` 声称自己是别人 | **拒绝**：服务端只认票据推出的身份 | D-0012 不变量 1 |
| 5 | 玩家在白天提交夜间行动 | 被**阶段闸**拒绝 | §4.2 ② |
| 6 | 玩家提交非法选项（僧侣保护自己） | 被**合法性闸**拒绝 | §4.2 ③ |
| 7 | 同一命令用同一幂等键重复投递 | 只生效一次，第二次返回同一结果 | §4.2 ④ |
| 8 | 玩家端抓包检查收到的全部数据 | **找不到**任何不属于他的信息（角色/阵营/标记/裁定） | §4.3 |
| 9 | 无关玩家观察某能力生效 | 从视图上**看不出**该能力发生过 | `docs/acceptance/AGENTS.md` §4 视角维 |
| 10 | 篡改前端 JS 后直接调 API 尝试越权 | 与第 1、4、8 行同样被拒绝（服务端不依赖前端） | D-0012 不变量 1 |
| 11 | 服务端日志检查 | 每次拒绝都有可定位的审计记录 | `AGENTS.md` 可观测性条款 |

> 第 8、10 行是**本票据存在的理由**：前端隐藏不算隔离，必须实测"抓包/篡改后拿不到"。
> 这两行只能靠真实运行验证，单元测试再绿也不算（`docs/evidence/verification.md` §6）。

## 备注

本票据**不包含**传输层加固（TLS、反向代理、限流）之外的东西；那些属于部署范畴，
在第一个可运行会话出现时一并处理并记录。
